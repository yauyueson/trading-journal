**版本**: 2.8 (Price Accuracy Fix + Code Audit P0/P1/P2)

**v2.8 新增（Price Accuracy Fix，2026-03-03）**:

**核心理念**: 
通过量化指标评估期权质量，避免主观判断和情绪化决策。

**两大评分系统**:
1. **LOQ** (Long Option Quality) - 买方评分
2. **CSQ** (Credit Spread Quality) - 卖方评分

**评分范围**: 0-100分
- **80-100**: 优秀机会
- **70-79**: 良好机会
- **60-69**: 一般机会
- **<60**: 不建议交易

## 📈 LOQ算法（买方评分）

### 1. 核心指标

#### Lambda (Λ) - 真实杠杆率

**定义**: 衡量期权的资本效率

**公式**:
```
Lambda = |Delta| × (Stock Price / Option Price)
```

**解释**:
- 高Lambda = 高杠杆，小资本控制大敞口
- 例: Delta=0.4, 股价=$620, 期权价=$7.36
  - Lambda = 0.4 × (620 / 7.36) = 33.7
  - 意味着$1期权价格变动相当于$33.7股票敞口

**理想范围**: 5-15
- <5: 杠杆不足，不如买股票
- 5-15: 黄金区间
- >20: 过度杠杆，触发**平滑压缩 (Soft Compression)**

#### Lambda Soft Compression (平滑压缩)

**目的**: 避免极低价格期权产生天文数字级的 Lambda 从而扭曲 Z-Score。

**公式**:
```
if (lambda <= 20):
  processed_lambda = lambda
else:
  processed_lambda = 20 + (lambda - 20) * 0.1
```

**效果**: Lambda=50 实际被压缩为 23，既保留了排名优势，又防止了数据爆炸。

**代码实现**:
```typescript
export function calculateLambda(
  delta: number, 
  stockPrice: number, 
  optionPrice: number
): number {
  if (optionPrice <= 0) return 0;
  return Math.abs(delta) * (stockPrice / optionPrice);
}
```

#### Gamma Efficiency (Γeff) - 爆发力

**定义**: 单位价格的Delta加速度

**公式**:
```
Gamma Efficiency = Gamma / Option Price
```

**解释**:
- 高Gamma Eff = Delta快速增长，有利方向移动时收益加速
- 例: Gamma=0.0123, 期权价=$7.36
  - Gamma Eff = 0.0123 / 7.36 = 0.00167
  - 股价每涨$1，Delta增加0.0123

**理想范围**: 0.01-0.05
- <0.01: Delta变化太慢
- 0.01-0.05: 黄金区间
- >0.05: 过度敏感，风险高

**代码实现**:
```typescript
export function calculateGammaEfficiency(
  gamma: number, 
  optionPrice: number
): number {
  if (optionPrice <= 0) return 0;
  return gamma / optionPrice;
}
```

---

#### Theta Burn (TB) - 时间衰减率

**定义**: 每日时间价值损失率

**公式**:
```
Theta Burn = |Theta| / Option Price
```

**解释**:
- 低Theta Burn = 每日损失少，适合持有
- 例: Theta=-0.0456, 期权价=$7.36
  - Theta Burn = 0.0456 / 7.36 = 0.0062 (0.62%/天)
  - 每天损失0.62%的期权价值

**理想范围**: 0-0.05
- <0.02: 优秀（<2%/天）
- 0.02-0.05: 可接受
- >0.05: 时间衰减过快

**代码实现**:
```typescript
export function calculateThetaBurn(
  theta: number, 
  optionPrice: number
): number {
  if (optionPrice <= 0) return 0;
  return Math.abs(theta) / optionPrice;
}
```

---

#### Theta Pain Curve - 指数型惩罚 (v2.2 新增)

**定义**: 对高时间衰减的非线性惩罚

**设计理念**:
- 安全区 (≤0.5%/天): 零惩罚，对 LEAPS 友好
- 超出安全区: 惩罚呈二次增长
- 封顶 50 分，防止极端值炸穿评分

**公式**:
```
if (thetaBurn <= 0.005):
  penalty = 0
else:
  excess = thetaBurn - 0.005
  penalty = min((excess × 100)² × 0.5, 10)
```

**示例**:
```
0.3%/天 → 0 (安全)
1.0%/天 → 0.125 分
3.0%/天 → 3.125 分
6.0%/天 → 10.000 分 (封顶)
```

**代码实现**:
```typescript
export function getThetaPenalty(thetaBurn: number): number {
  const SAFE_ZONE = 0.005; 
  
  if (thetaBurn <= SAFE_ZONE) {
    return 0;
  }
  
  const excess = thetaBurn - SAFE_ZONE;
  const penalty = Math.pow(excess * 100, 2) * 0.5;
  
  return Math.min(penalty, 10);
}
```

#### Gamma/Theta Ratio (G/T) - Gamma 性价比 (v2.2 新增)

**定义**: 衡量每单位 Theta 损耗获得的 Gamma 加速度

**公式**:
```
G/T = Gamma / |Theta|
```

**解释**:
- 高 G/T = Gamma 便宜，时间衰减换来的 Delta 加速多
- 低 G/T = Gamma 昂贵，每天付出的 Theta 换来的 Gamma 少
- 例: Gamma=0.02, Theta=-0.01
  - G/T = 0.02 / 0.01 = 2.0
  - 每损耗 $0.01 Theta，获得 0.02 的 Delta 加速

**理想范围**: 0.5-3.0
- <0.3: Gamma 过贵，不划算
- 0.5-3.0: 合理区间
- >5.0: 触发**平滑压缩 (Soft Compression)**

#### G/T Soft Compression (平滑压缩)

**目的**: 当 Theta 极小（如 LEAPS）时 G/T 可能爆炸，需要衰减。

**公式**:
```
if (|theta| < 0.001):
  G/T = gamma > 0 ? 5 : 0     // 封顶
else if (G/T <= 5):
  processed_GT = G/T
else:
  processed_GT = 5 + (G/T - 5) * 0.1
```

**效果**: G/T=10 被压缩为 5.5，保留排名优势但防止 Z-Score 爆炸。

**代码实现**:
```typescript
export function calculateGammaThetaRatio(gamma: number, theta: number): number {
    const absTheta = Math.abs(theta);
    if (absTheta < 0.001) return gamma > 0 ? 5 : 0;
    const raw = gamma / absTheta;
    const THRESHOLD = 5;
    const DECAY_RATE = 0.1;
    if (raw <= THRESHOLD) return raw;
    return THRESHOLD + (raw - THRESHOLD) * DECAY_RATE;
}
```

**与其他指标的关系**:
| 指标 | 衡量维度 | 回答的问题 |
|------|----------|-----------|
| Gamma Efficiency | Gamma / 期权价 | 每投入 $1 获得多少 Gamma？ |
| Theta Burn | \|Theta\| / 期权价 | 每天损失投资额的百分之几？ |
| **G/T Ratio** | **Gamma / \|Theta\|** | **每付出 $1 Theta 获得多少 Gamma？** |

三者共同构成完整的"Gamma 成本分析"：G/T 直接衡量 Gamma 和 Theta 之间的**性价比关系**，而非各自与价格的关系。

#### Breakeven Move % - 真实到期回本难度 (v2.3 改进)

**定义**: 到期时股价需要移动多少百分比，买方才能回本

**v2.3 改动**: 从 delta 线性近似改为 **strike-based 真实到期 breakeven**。

旧公式 `premium / (|Δ| × S)` 对深 OTM / 高 Gamma 区严重偏离——某些合约被误判"回本要求不高"，实际到期 breakeven 很远。新公式直接用 strike，精确无误。

**公式 (v2.3)**:
```
Call:  BE = K + premium     → Move% = |BE - S| / S
Put:   BE = K - premium     → Move% = |BE - S| / S

其中:
- K = 行权价 (strike)
- premium = (bid + ask) / 2
- S = 标的股价 (currentPrice)
```

**示例对比**:
```
SPY $600, Call K=610, mid=$3.50, delta=0.35:
  旧 (delta): 3.50 / (0.35 × 600) = 1.67%  ← 偏小
  新 (strike): |610+3.50-600| / 600 = 2.25%  ← 真实

SPY $600, Call K=650, mid=$0.50, delta=0.05:
  旧 (delta): 0.50 / (0.05 × 600) = 1.67%  ← 严重失真！
  新 (strike): |650+0.50-600| / 600 = 8.42%  ← 彩票合约现形

SPY $600, Put K=580, mid=$2.00:
  新 (strike): |580-2.00-600| / 600 = 3.67%
```

**DTE 归一化**:
不同到期日的期权，合理 Breakeven 不同。60 天期权允许更大的波动范围。

```
DTE Factor = sqrt(DTE / 30)
Adjusted BE = Breakeven Move / DTE Factor

示例:
  BE=5%, DTE=30 → Adjusted=5.0% (参考基准)
  BE=5%, DTE=60 → Adjusted=3.5% (60天有更多时间)
  BE=5%, DTE=7  → Adjusted=10.4% (7天内要涨5%很难)
```

**Penalty/Bonus 曲线 (LERP)**:
```
Adjusted BE ≤ 2%:    +0.5  (很容易达到)
Adjusted BE 2-5%:    lerp(+0.5, 0)
Adjusted BE 5-10%:   lerp(0, -1.0)
Adjusted BE 10-20%:  lerp(-1.0, -2.0)
Adjusted BE > 20%:   -2.0  (封顶，极不现实)
```

**代码实现 (v2.3)**:
```typescript
export function calculateBreakevenMove(
    strike: number, premium: number, stockPrice: number, optionType: 'Call' | 'Put'
): number {
    if (stockPrice <= 0) return 1;
    const breakeven = optionType === 'Call' ? strike + premium : strike - premium;
    return Math.abs(breakeven - stockPrice) / stockPrice;
}

export function getBreakevenPenalty(breakevenMove: number, dte: number): number {
    const dteFactor = dte > 0 ? Math.sqrt(dte / 30) : 1;
    const adjusted = breakevenMove / dteFactor;

    if (adjusted <= 0.02) return 0.5;
    if (adjusted <= 0.05) return lerp(adjusted, 0.02, 0.05, 0.5, 0);
    if (adjusted <= 0.10) return lerp(adjusted, 0.05, 0.10, 0, -1.0);
    if (adjusted <= 0.20) return lerp(adjusted, 0.10, 0.20, -1.0, -2.0);
    return -2.0;
}
```

**需要的字段**: strike K、mid premium、underlying price S、optionType — 链上全部具备。

**与 Delta Bonus 的区别**:
| 指标 | 衡量角度 | 输入 |
|------|----------|------|
| Delta Bonus | 期权的 moneyness 类别 | 仅 Delta |
| **Breakeven Move** | **到期时真实回本所需的股价变动** | **strike + premium + 股价 + DTE** |

Delta Bonus 回答"这个 Delta 好不好"，Breakeven Move 回答"这笔交易到期能回本吗"。两者互补。

#### Delta Bonus - ATM奖励

**定义**: 奖励ATM期权，惩罚彩票式期权

**规则 (LERP 线性插值)**:
为了避免 Delta 在 0.14 和 0.15 之间产生巨大的评分分水岭，我们使用线性插值：

- **|Δ| < 0.15**: -2.0 定值 (彩票惩罚)
- **|Δ| 0.15 - 0.30**: 从 -2.0 线性过渡到 -0.5
- **|Δ| 0.30 - 0.50**: 从 -0.5 线性过渡到 +1.0 (甜蜜区)
- **|Δ| 0.50 - 0.70**: 从 +1.0 线性过渡到 +0.5
- **|Δ| > 0.70**: 从 +0.5 线性过渡到 0 (深度 ITM)

**代码实现**:
```typescript
export function getDeltaBonus(delta: number): number {
  const absDelta = Math.abs(delta);
  const lerp = (x, x1, x2, y1, y2) => y1 + (y2 - y1) * ((x - x1) / (x2 - x1));

  if (absDelta < 0.15) return -2.0;
  if (absDelta < 0.30) return lerp(absDelta, 0.15, 0.30, -2.0, -0.5);
  if (absDelta < 0.50) return lerp(absDelta, 0.30, 0.50, -0.5, 1.0);
  if (absDelta < 0.70) return lerp(absDelta, 0.50, 0.70, 1.0, 0.5);
  return lerp(absDelta, 0.70, 1.0, 0.5, 0);
}
```

### 3. Z-Score标准化 — DTE 分桶归一化 (v2.3 改进)

**问题**: 旧版 Z-Score 在全池内计算。7-DTE 的极端 Gamma/Price 与 45-DTE 在同一池比较，扭曲 Z-Score 分布。

**解决**: 按 DTE 分桶计算 Z-Score，每个桶内独立归一化。同行比同行。

**DTE 桶**:
```typescript
export const DTE_BUCKETS = [
    { label: '0-14',   min: 0,   max: 14  },
    { label: '15-30',  min: 15,  max: 30  },
    { label: '31-60',  min: 31,  max: 60  },
    { label: '61-120', min: 61,  max: 120 },
    { label: '121+',   min: 121, max: Infinity },
];

export const MIN_BUCKET_SIZE = 3; // 桶内不足 3 个则回退到全池统计
```

**公式**:
```
对每个 DTE 桶 b:
  μ_b = mean(values in bucket b)
  σ_b = std(values in bucket b)

Z_i = (x_i - μ_b) / σ_b    // 使用所属桶的统计量
      若桶内 < 3 个，退回 (x_i - μ_pool) / σ_pool
```

**优雅退化**:
- 窄 DTE 扫描（如 30-45）→ 全部落入同一桶 → 等价于旧行为
- 小结果集 → 桶内不足 3 个 → 自动回退到全池统计
- 宽 DTE 扫描（如 5-90）→ 分桶生效，7-DTE 和 45-DTE 各自组内比较

**代码实现**:

  - IV_Adj = 0: 0
```

## 📉 CSQ算法（卖方评分）

### 1. 核心指标

#### POP (Probability of Profit)

**定义**: 期权到期时盈利的概率

**优先级（v2.5 更新）**:
1. **市场提供的 probabilityITM**（Polygon 字段，最准确）
2. **Breakeven 处的 Delta 插值**（链上插值）
3. **BSM N(d2) 回退**（v2.5 新增，比旧的 `1-|delta|` 更准确）

```
# 信用价差（卖方）
POP = 1 - P(S < breakeven)  →  1 - (1 - N(d2))  =  N(d2)
                                where d2 = (ln(S/K) - 0.5σ²T) / (σ√T)
# 旧回退（已废弃）
POP = 1 - |Delta|   ← 对 OTM 期权误差最大可达 ±0.15
```

**代码实现** (`src/lib/bsm.ts`):
```typescript
export function bsmN2(S: number, K: number, T: number, sigma: number): number {
  if (T <= 0 || sigma <= 0 || S <= 0 || K <= 0) return 0.5;
  const d2 = (Math.log(S / K) - 0.5 * sigma * sigma * T) / (sigma * Math.sqrt(T));
  return normCDF(d2);
}
// 信用价差（put）：pop = 1 - bsmN2(S, breakeven, T, iv)
// 借方价差（call）：pop = bsmN2(S, breakeven, T, iv)
```

---

#### Seller's Edge - 卖方优势

**定义**: 期望收益

**公式**:
```
Edge = POP × Premium Received
```

**解释**:
- 结合概率和收益的期望值
- 例: POP=0.70, Premium=$2.50
  - Edge = 0.70 × 2.50 = $1.75
  - 期望每份合约赚$1.75

**代码实现**:
```typescript
export function calculateSellerEdge(pop: number, premium: number): number {
  return pop * premium;
}
```

---

#### Spread Percentage - 流动性

**定义**: 买卖价差占比

**公式**:
```
Spread% = (Ask - Bid) / Mid
```

**解释**:
- 低Spread = 高流动性，易成交
- 例: Bid=$2.45, Ask=$2.55
  - Mid = $2.50
  - Spread% = 0.10 / 2.50 = 4%

**理想范围**: <10%
- <5%: 优秀流动性
- 5-10%: 可接受
- >10%: 流动性差

**代码实现**:
```typescript
export function calculateSpreadPct(bid: number, ask: number): number {
  const mid = (bid + ask) / 2;
  if (mid <= 0) return 1; // 100% = 无流动性
  return (ask - bid) / mid;
}
```

## 🌡️ IV期限结构分析

### 1. 4-Card Method

**目的**: 判断市场波动率环境

**方法**: 比较30天和90天ATM IV

**步骤**:
1. 找到30天到期的ATM Call和Put
2. 平均得到IV_30
3. 找到90天到期的ATM Call和Put
4. 平均得到IV_90
5. 计算比率: IV_Ratio = IV_30 / IV_90

**代码实现**:
```typescript
function getATMIV(
  chain: OptionData[],
  currentPrice: number,
  targetDTE: number,
  tolerance: number = 10
): number | null {
  // 1. 筛选目标DTE附近的Call
  const candidates = chain.filter(
    opt => opt.type === 'Call' && Math.abs(opt.dte - targetDTE) <= tolerance
  );
  
  if (candidates.length < 2) return null;
  
  // 2. 按行权价排序
  candidates.sort((a, b) => a.strike - b.strike);
  
  // 3. 找到夹住当前价格的两个行权价
  for (let i = 0; i < candidates.length - 1; i++) {
    if (candidates[i].strike <= currentPrice && 
        candidates[i + 1].strike >= currentPrice) {
      return (candidates[i].iv + candidates[i + 1].iv) / 2;
    }
  }
  
  // 4. 降级：使用最接近的行权价
  const closest = candidates.reduce((prev, curr) =>
    Math.abs(curr.strike - currentPrice) < Math.abs(prev.strike - currentPrice) 
      ? curr : prev
  );
  return closest.iv;
}

export function calculateIVRatio(
  chain: OptionData[], 
  currentPrice: number
): IVTermResult {
  const iv30 = getATMIV(chain, currentPrice, 30);
  const iv90 = getATMIV(chain, currentPrice, 90);
  
  if (!iv30 || !iv90 || iv90 === 0) {
    return { ivRatio: 1.0, iv30, iv90, status: 'neutral' };
  }
  
  const ratio = iv30 / iv90;
  
  let status: 'contango' | 'neutral' | 'backwardation';
  if (ratio < 0.95) {
    status = 'contango';      // 近期IV低，适合买入
  } else if (ratio > 1.05) {
    status = 'backwardation';  // 近期IV高，适合卖出
  } else {
    status = 'neutral';        // 正常状态
  }
  
  return { ivRatio: ratio, iv30, iv90, status };
}
```

**策略推荐 API 的 Regime 增强（期限结构斜率 + Anomaly 降权）**：
- **期限结构斜率**：`slope = (IV30−IV90)/IV90`，档位 `slopeTier` 为 strong_backwardation / backwardation / flat / contango / strong_contango。用于微调 `calculateRegimeBonus`：Strong backwardation 时 Credit 再 +2；Strong contango 时 Debit/Long 再 +2。
- **Anomaly 与统一分**：当 `ivSurface.anomaly === true`（IV7/IV30 > 1.3）时，除 advice 文案外，在**统一分**中对「短期卖权」降权：CREDIT_SPREAD 且 DTE ≤ 30 的候选，Regime 分量 ×0.55，使 Top Picks 排序中短期信用价差下移。实现见 `api/_shared/scoring.cjs` 的 `calculateUnifiedScore(..., opts)`（opts.anomaly、opts.termStrength）。

> **v2.7 IV 插值修正说明**：旧版 `calculateTargetIV` 对 IV（波动率）做线性插值。方差（σ²·T）才是时间线性的量（CBOE VIX 方法论同原理）。在 Backwardation 时（如 IV30=30%，IV90=20%），线性插值给出 IV60=25.0%，而正确的方差插值给出 IV60=22.9%（误差约 2pp）。对应修复：
> ```
> varNear = ivNear² × nearDTE / 252
> varFar  = ivFar²  × farDTE  / 252
> varTarget = lerp(targetDTE, nearDTE, farDTE, varNear, varFar)
> iv_target = √(varTarget × 252 / targetDTE)
> ```

### 2. IV调整规则 (Sigmoid 平滑过渡, v2.7 调谐)

**设计理念**:
- 市场情绪在"冷静"和"恐慌"之间突变
- 使用 Sigmoid 函数模拟这种相变
- k=8 提供更平滑的过渡（v2.7 从 k=12 下调，减少假信号）
- x0=1.00 作为临界点（v2.7 从 x0=1.10 下调，中性锚定在 ratio=1.0）

**IV Risk Factor 公式**:
```
riskFactor = 0.9 + sigmoid(ratio, k=8, x0=1.00) × 0.4

返回值:
- ~0.9 = 安全 (Contango, ratio < 0.90)
- ~1.1 = 中性 (ratio ≈ 1.00)
- ~1.3 = 危险 (Backwardation, ratio > 1.10)
```

**买方（LOQ）调整**:
```
IV_Adj = (1 - riskFactor) × 5

- riskFactor=0.9 → +0.5 (Contango 奖励)
- riskFactor=1.1 → -0.5 (轻微 Backwardation 惩罚)
- riskFactor=1.3 → -1.5 (Backwardation 惩罚)
```

**卖方（CSQ）调整**:
```
IV_Adj = (riskFactor - 1) × 5

- riskFactor=0.9 → -0.5 (Contango 惩罚)
- riskFactor=1.1 → +0.5 (轻微 Backwardation 奖励)
- riskFactor=1.3 → +1.5 (Backwardation 奖励，卖高IV)
```

**代码实现**:
```typescript
export function getIVRiskFactor(ratio: number): number {
  const k = 8;      // Steepness (v2.7: 12→8, smoother transition)
  const x0 = 1.00;  // Critical point (v2.7: 1.10→1.00, neutral at ratio=1)

  const raw = 1 / (1 + Math.exp(-k * (ratio - x0)));

  return 0.9 + raw * 0.4;
}

export function getIVAdjustment(ivRatio: number, strategy: Strategy): number {
  const riskFactor = getIVRiskFactor(ivRatio);
  
  if (strategy === 'long') {
    return (1 - riskFactor) * 5;
  } else {
    return (riskFactor - 1) * 5;
  }
}
```

### 3. IV Rank 纵向对比 (v2.2)

**目的**: 期限结构（IV30/IV90）只反映「近期 vs 远期」相对关系，不反映当前 IV 在**历史**中的位置。IV Rank 回答：当前 IV 在过去 252 个交易日中处于什么分位？

**定义**:
- **IV Rank** = (当前 IV30 − 52 周最低 IV30) / (52 周最高 IV30 − 52 周最低 IV30)，取值 [0, 1]
- **IV Percentile** = 过去 252 天中有多少天的 IV30 低于当前值，比例 [0, 1]

**数据来源**: 表 `ticker_iv_snapshots`。
- **每日自动积累**：每次 Scanner 或 Strategy Recommender 请求会 upsert 当日 (ticker, recorded_date, iv30, iv90) 的当前市场 ATM IV。
- **历史回填 (Polygon)**：由于 Polygon 不提供免费的长周期历史 IV 数据，在迁移初期使用 **RV30 (30日标的历史已实现波动率)** 作为历史 IV30 的代理值进行回填。
- **回填方式**：通过 `cron-iv-snapshot.js` 每日积累；初期曾使用 RV30 代理回填（已完成，标记 `source='rv_proxy'`）。
- **计算策略**：获取 252+ 交易日的 K 线，计算滚动 RV30。

无历史时 IV Rank 调整为 0。

**置信度缩放 (v2.7)**：当历史样本不足时，IV Rank 调整按 `confidence = min(1, sampleDays / 180)` 缩放。需要约 180 天（252 日回看窗口的 ¾）才能达到完全置信。

**评分调整** (与期限结构调整**叠加**, 已乘以 confidence):
```
若 ivRank == null: 不调整
买方 (long):
  ivRank < 0.3  → +0.5  (IV 便宜，适合买)
  ivRank > 0.7  → -0.5  (IV 贵，不适合买)
卖方 (short):
  ivRank < 0.3  → -0.3  (IV 便宜，不适合卖)
  ivRank > 0.7  → +0.5  (IV 贵，适合卖)
```

**API**: `GET /api/iv-rank?ticker=QQQ` 返回 `{ ivRank, ivPercentile, currentIv30, minIv, maxIv, sampleDays }`。

**策略推荐中的使用**：`api/strategy-recommend.js` 在每次请求时先以当前链数据 `buildIVTermStructure` 得到 iv30/iv90，调用 `saveTickerIVSnapshot(upperTicker, iv30, iv90)` 写入当日快照，再调用 `getIVRank(upperTicker)`（`ivHistory.cjs`，读表 `ticker_iv_snapshots`）得到 ivRank。随后用 `getIVRankAdjustment(ivRank, strategy)` 参与三类策略打分：
- **Single-leg (LOQ)**：`strategy = 'long'`，ivRankAdj 与 ivAdjustment 一起传入 `calculateLOQRaw`；
- **Credit Spread（卖方）**：`strategy = 'short'`，`finalScore += ivRankAdj * 2`；
- **Debit Spread（买方）**：`strategy = 'long'`，`finalScore += ivRankAdj * 2`。

这样 backfill 与日常请求使用同一套数据源（当前链的 iv30）写入快照，IV Rank 会随时间积累变准。策略推荐 API 返回 `regime.ivRank`、`regime.ivPercentile`；**策略推荐页**（StrategyRecommender）在 regime 区域同时展示 **IV Rank** 与 **IV Percentile**（Rank XX%、%ile XX%，同色阶：低=便宜/绿、高=贵/黄）。

## 💰 P&L计算算法

### 3. P&L计算 (买方/单腿模式)

**未实现P&L**:
```
Unrealized P&L = (Current Price - Average Cost) × Current Quantity × 100
```

**已实现P&L**:
```
Realized P&L = Σ(Sell Price - Average Cost) × Sell Quantity × 100
```

### 4. 卖方价差 (Credit Spread) 特殊核算

对于卖方信用价差（Credit Spread），系统采用“平仓成本（Cost to Close）”逻辑：

**平仓成本 (Cost to Close)**:
```
Cost to Close = Short Leg Price - Long Leg Price
(始终保持为正值，反映当前平仓所需支付的净权利金)
```

**未实现 P&L**:
```
Unrealized P&L = (Entry Credit - Current Cost to Close) × Quantity × 100
```

**逻辑解释**:
- 开仓时获得 $1.00 (Entry Credit)
- 当前平仓需支付 $0.80 (Cost to Close) → 盈利 $0.20
- 当前平仓需支付 $1.20 (Cost to Close) → 亏损 $0.20

**代码实现 (PositionCard.tsx)**:
```typescript
if (isCreditStrategy) {
    // 信用价差：平仓成本 = 空头价格 - 多头价格
    netPrice = shortPrice - longPrice;
    unrealizedPnL = (entryPrice - netPrice) * quantity * 100;
} else {
    // 借方/买方：持仓价值 = 现价 - 成本
    unrealizedPnL = (currentPrice - avgCost) * currentQty * 100;
}
```

## 📊 组合评分算法 (Spread Scoring)

系统对价差策略（Spreads）采用综合特征评分，确保 Portfolio 与 Option Selector 评分一致。

### 1. 信用价差评分 (Credit Spread Score - CSQ+, v2.2 EV-Enhanced)

**核心权重** (v2.2 / v2.5 EV 修正):
- **EV (30%)**: 完整期望值 = POP × Credit - (1-POP) × MaxRisk × **0.75**（v2.5：加入退出乘数，反映实际提前平仓）。综合风险与收益的核心指标。
- **ROI (25%)**: 权利金 / 最大风险。25% ROI 达到满分。
- **POP (25%)**: 盈利概率 (1 - |Short Delta|)。
- **Distance (20%)**: 行权价距离股价的深度。10% OTM 达到满分。

**EV 评分映射**:
```
evRatio = EV / Credit    // 期望收益占权利金的比例
scoreEV = clamp(50 + evRatio × 100, 0, 100)

示例:
  evRatio = +0.50 → 100 (优秀：期望保留50%权利金)
  evRatio = +0.25 → 75  (良好)
  evRatio =  0.00 → 50  (盈亏平衡)
  evRatio = -0.25 → 25  (负EV)
  evRatio = -0.50 → 0   (严重负EV)
```

**为什么需要 EV + ROI + POP 三维？**
- ROI 只看上行：25% ROI 可能来自高概率小赢或低概率大赢
- POP 只看概率：90% POP 但赚 $0.10 赔 $4.90 实际 EV 为负
- **EV 整合两者**：唯一回答"这笔交易数学上是否值得"的指标

**代码逻辑** (v2.2 / v2.5 exit multiplier):
```typescript
// calculateExpectedValue(pop, credit, maxRisk, exitMultiplier=0.75)
const ev = calculateExpectedValue(pop, credit, maxRisk); // 默认 0.75
const evRatio = credit > 0 ? ev / credit : 0;
const scoreEV = Math.max(0, Math.min(100, 50 + evRatio * 100));

const scoreROI = Math.min(roi * 4, 100); 
const scorePOP = pop * 100;
const scoreDistance = Math.min(distance * 1000, 100); 

finalScore = Math.round(0.30 * scoreEV + 0.25 * scoreROI + 0.25 * scorePOP + 0.20 * scoreDistance);
```

### 2. 借方价差评分 (Debit Spread Score - LOQ+)

**核心权重**:
- **Lambda (40%)**: 组合杠杆率。
- **Risk/Reward (35%)**: 盈亏比。1:3 R:R 达到满分。
- **Delta Bonus (25%)**: 组合 Delta 对方向性的奖励。

**代码逻辑**:
```typescript
const lambdaScore = Math.min((compLambda / 20) * 100, 100); 
const rrScore = Math.min((riskReward / 3) * 100, 100);      
const deltaScore = 50 + deltaBonus * 12.5;

finalScore = Math.round(0.4 * lambdaScore + 0.35 * rrScore + 0.25 * deltaScore);
```

## 📈 Tech Score（技术面自动化评分）

### 概述
**Tech Score** 是 2.4 版本引入的自动化技术面分析系统。逻辑与 TradingView 上的 Pine Script 指标「MB+DFP + Options Scanner」一致：将 Market Bias、B-Xtrender、EMA Stack、动量等移植到 Javascript/TypeScript，对 K 线（OHLC）计算后得到 0–100 的技术面综合分。

**分值范围**: **0–100**（加权综合分）
- **85–100**: 强信号（STR BUY / STR SELL 或 BUY / SELL）
- **70–84**: 中等信号（BUY / SELL）
- **60–69**: 观察（WATCH）
- **0–59**: 偏弱或未达最小阈值

综合分由五个子分数加权平均得到，每个子分数基准为 50，再根据多空与强度加减分。

### 1. 五个组成指标与权重

| 组件 | 权重 | 说明 |
|------|------|------|
| **Market Bias** | 30% | 基于 Heikin Ashi 平滑后的振荡器 |
| **B-Xtrender Short** | 25% | 短周期 RSI 衍生，T3 平滑 |
| **B-Xtrender Long** | 20% | 长周期 RSI 衍生 |
| **EMA Stack** | 15% | 8/21/34 均线排列与价格距离 |
| **Momentum** | 10% | 1 根 K 与 3 根 K 的涨跌幅 |

### 2. 各组件计算要点（与 Pine 一致）

#### A. Market Bias (30%)
- **周期**: Market Bias 周期 20，Smoothing 7，Oscillator 7（与 Scanner 设置一致）。
- **流程**: 对 O、H、L、C 分别做 EMA(20) → 用这四条序列构造 Heikin Ashi → 对 HA 的 open/close 再做 EMA(7) → 振荡器 `osc = 100*(c2 - o2)`，再对 osc 做 EMA(7) 平滑。
- **子分**: `sc_mb = 50 + (多头 ? min(osc*5, 30) : -min(|osc|*5, 30)) + (强势 ? 20 : 5)`。

#### B. B-Xtrender Short (25%)（v2.7 方向感知修正）
- **周期**: Short L1=5, L2=20, L3=5；T3 平滑周期 5。
- **计算**: `stX = RSI(EMA(close,5) - EMA(close,20), 5) - 50`，再 `mstX = T3(stX, 5)`。反转由 mstX 的局部极值判断。
- **子分（v2.7 修正）**：方向感知；看空反转 (`rev_dn`) 现在**减**分，MA 方向下行现在减分：
  ```
  sc_bxs = 50
         + clamp(bxs×2, -50, +50)    // 有方向的核心项（原有）
         + (mstX 上升 ? +10 : -5)     // MA 斜率（旧版下行仍给 +5，现在给 -5）
         + (rev_up ? +15 : rev_dn ? -15 : 0)  // 方向感知（旧版两者均 +15）
  ```

#### C. B-Xtrender Long (15%)
- **计算**: `ltX = RSI(EMA(close,20), 5) - 50`（Long L1=20, L2=5）。
- **子分**: `sc_bxl = 50 + clamp(bxl*3, -50, 50)`。

#### D. EMA Stack (15%)（v2.7 方向感知修正）
- **均线**: EMA(close, 8)、EMA(close, 21)、EMA(close, 34)。
- **逻辑**: 价格与三条线的距离百分比 d8、d21；多头排列 e8 > e21 > e34（`bullStack`），空头排列相反（`bearStack`）。
- **子分（v2.7 修正）**：多空对称，旧版对所有配置均加分（范围 60-100）；新版范围 0-100，方向对称：
  ```
  bull_ema = d8 > 0 && d21 > 0       // 价格在 EMA 之上 → 加分
  sc_ema = 50
         + (bull_ema ? +1 : -1) × (10 + signStrength × 15)  // 方向±10/-10
         + (bullStack ? +1 : bearStack ? -1 : 0) × (5 + stackStrength × 20)
  // 旧版：sc_ema += 10 + ... + 5 + ...（永远加分）
  ```

#### E. Momentum (10%)（v2.7 方向感知修正）
- **计算**: `ch1 = (close - close[1])/close[1]*100`，`ch3 = (close - close[3])/close[3]*100`。
- **子分（v2.7 修正）**：带符号，旧版用 `Math.abs()` 导致暴跌与上涨评分相同（永久多头偏差）：
  ```
  sc_mom = 50
         + sign(ch1) × min(|ch1|/2, 1) × 20   // 正涨 → 加；负跌 → 减
         + sign(ch3) × min(|ch3|/5, 1) × 20
  // 旧版：sc_mom += 5 + min(|ch1|/2,1)×20 + 5 + min(|ch3|/5,1)×20（永远加分）
  ```
> **范围变化**: 所有三个组件（BXS/EMA/Momentum）修正后理论范围从 `[50+, 100]` 变为 `[0, 100]`，在送入加权前统一钳位到 `[0, 100]`。

### 3. 综合分与信号
- **综合分**: `comp = (sc_mb*w_mb + sc_bxs*w_bxs + sc_bxl*w_bxl + sc_ema*w_ema + sc_mom*w_mom) / 100`，默认权重 30/25/20/15/10（Market Bias / B-X Short / B-X Long / EMA Stack / Momentum）。
- **信号与设置名称**: 由 `comp`、方向（CALL/PUT）及 s_identify 逻辑得到（如 Perfect Storm、Squeeze Breakout、Breakout 等），与 Pine 表列一致。

### 4. 数据与触发
1. **数据**: 通过 Polygon API 获取日线 K 线（约 400 根），与 TradingView 1D 对比时请使用同一标的、同一「截至日」。
2. **自动化**: 每日打开 Portfolio 时触发批量刷新技术面；同一标的在纽约时间同一天内仅自动更新一次（NY Time 冷却）。

### 5. 代码实现参考
- `src/lib/tech-analysis.ts`（或 `lib/tech-analysis.js`）：`calculateTechScore(candles, options?)`。默认与 Scanner 一致：Market Bias 周期 20、Smoothing 7、Oscillator 7；B-Xtrender Short L1/L2/L3=5/20/5，Long L1/L2=20/5；权重 30/30/15/15/10。可选参数 `options` 可覆盖上述权重与周期。
- `src/lib/indicators.ts`：EMA、RSI、T3、Heikin Ashi 等基础指标。

## 💰 Earnings IV Premium 估算（v2.5 新增）

当期权跨越财报日（`daysUntilEarnings ≤ DTE`）时，系统自动附加财报 IV 溢价估算。

### 公式

```
隐含财报移动（$）= IV × √(1/252) × 股价
隐含财报移动（%）= IV × √(1/252) × 100

事后 IV 估算 = IV × √((DTE-1)/DTE)
（假设财报事件消耗 1 天跳跃方差后，IV 回落）
```

### 含义

| 字段 | 说明 |
|------|------|
| `impliedEarningsMove` | 财报当天的 1 标准差预期移动（美元） |
| `earningsMovePct` | 同上，以股价百分比表示 |
| `postEarningsIVEstimate` | 财报后 IV 预估值（%），用于评估 IV crush 幅度 |

### 使用场景

- **借方价差（买方）**：财报移动 > 2 × 行权价间距时，满足触发条件的概率更高
- **信用价差（卖方）**：财报溢价大时，收到的权利金偏高但风险也大
- **Option Selector页**：`context.earningsPremium` 在顶部 context 区显示（使用 IV30 估算）

> **v2.7 财报模型改进**：旧版用 `postIV = iv × √((DTE-1)/DTE)` 低估 IV crush（7 DTE 高估约 10pp）。v2.7 改为**方差分解**：
> ```
> totalVar = iv² × DTE / 252
> dailyVar = totalVar / DTE
> jumpVar  = max(0, totalVar - dailyVar × (DTE-1))  // 剥离跳跃方差
> diffuseVar = totalVar - jumpVar
> postIV = √(diffuseVar × 252 / (DTE-1))
> ```
> 7 DTE / IV=50% 示例：旧版 postIV=46.3% → 新版 postIV ≈ 50%（跳跃方差即为单日扩散方差 1/7，数学上守恒）。真正差异在于财报当天隐含跳跃幅度的计算更精确：`impliedEarningsMove = √jumpVar × S`。

## 🦅 Iron Condor Builder（v2.6 新增）

### 设计理念

Iron Condor = 一个看跌信用价差（下方）+ 一个看涨信用价差（上方），同一到期日。适合 Pine Script 推荐 `Bullish/Bearish + Range 环境` 的场景。

### 核心算法 `buildIronCondors()`

**第一步：DTE 筛选**
```
IC 甜蜜区：21–60 DTE（Theta 衰减可控 + 足够的 Breakeven 缓冲）
财报保护：daysUntilEarnings ≤ 10 → 跳过该到期日
```

**第二步：空头腿定位（15–25Δ）**
```
shortPut :  PUT side,  |Δ| ∈ [0.15, 0.25], strike < currentPrice
shortCall: CALL side, |Δ| ∈ [0.15, 0.25], strike > currentPrice

理论依据：15–25Δ ≈ 70–85% POP 每侧，与保险公司精算思路一致
```

**第三步：保护腿选取**
```
longPutStrike  = shortPut.strike  - width  (默认宽度 5 或 10 点)
longCallStrike = shortCall.strike + width
```

**第四步：四腿流动性检查**
```
对每条腿 (shortPut, longPut, shortCall, longCall)：
  mid ≥ HARD_FILTER_CREDIT.minMid (0.10)
  openInterest ≥ HARD_FILTER_CREDIT.minOpenInterest (150)
putSpreadPct, callSpreadPct ≤ HARD_FILTER_CREDIT.maxSpreadPctCeiling (12%)
```

**第五步：信用与风险计算**
```
putCredit  = (shortPut.bid + shortPut.ask)/2 - (longPut.bid + longPut.ask)/2
callCredit = (shortCall.bid + shortCall.ask)/2 - (longCall.bid + longCall.ask)/2
totalCredit = putCredit + callCredit

maxRisk = width - totalCredit   // 只有一侧会产生最大亏损
          (假设最坏情况下另一侧亦到期无价值)
```

**第六步：滑点建模（四腿）**
```
totalSlippage = Σ estimateSlippage(bid_i, ask_i, OI_i)  for i in [4 legs]
effectiveCredit = totalCredit - totalSlippage
effectiveROI = effectiveCredit / (width - effectiveCredit) × 100
硬过滤：effectiveROI < 8% → 丢弃
```

**第七步：POP 估算（BSM）**
```
iv_avg = (shortPut.iv + shortCall.iv) / 2
lowerBE = shortPut.strike  - totalCredit
upperBE = shortCall.strike + totalCredit
T = dte / 365

pAboveLower = N(d2(S, lowerBE, T, iv_avg))  // P(S > lowerBE)
pAboveUpper = N(d2(S, upperBE, T, iv_avg))  // P(S > upperBE)
POP = pAboveLower - pAboveUpper              // P(lowerBE < S < upperBE)
```

**第八步：对称性计算**
```
putDistance  = (currentPrice - shortPut.strike)  / currentPrice
callDistance = (shortCall.strike - currentPrice)  / currentPrice
symmetryRatio = min(putDistance, callDistance) / max(putDistance, callDistance)
// 1.0 = 完美对称；< 0.7 = 偏斜明显
```

**第九步：综合评分**

| 维度 | 权重 | 说明 |
|------|------|------|
| POP | 40% | 价格维持在盈亏平衡区间内的概率 |
| Credit/Risk（ROI） | 25% | 有效信用/最大风险（min(ROI×3, 100)） |
| 翼部对称性 | 15% | 偏斜的 IC 单侧风险敞口更大 |
| DTE 高斯曲线 | 20% | 峰值在 37 DTE，±15 标准差 |

```
scorePOP      = POP × 100
scoreROI      = min(effectiveROI × 3, 100)
scoreSymmetry = symmetryRatio × 100
scoreDTE      = 100 × exp(-0.5 × ((DTE-37)/15)²)

finalScore = 0.40×POP + 0.25×ROI + 0.15×Symmetry + 0.20×DTE
           + ivRankAdj×2
           + 8 (if ivRvRatio > 1.20, IV 偏贵对卖方有利)
           + 5 (if ivRvRatio > 1.40)
           - 25 (if anomaly && DTE ≤ 35, IV 异常飙升惩罚)
           - 20 (if includesEarnings)
```

## 🖥️ Pine Script (TV) Scanner v3.2 信号发生算法

TradingView 的 `MB_DFP_Options_Scanner_v3.2` 是期权交易的前置信号引擎。它通过多个技术维度的融合，提供一个结构化的推荐体系（Setup, Target Strategy, 0-100 Score, Tier），并包含了严格的历史回测系统，供后续在 Web App 中执行。

### 1. 技术面评分体系 (Tech Score, 0-100)

**五大维度:**
1. **MacdBulls (w_mb, 默认 35%)**: 衡量短期爆发动能。计算波段极值并使用标准化公式。
2. **Boxer Short & Long (w_bxs 25%, w_bxl 20%)**: 结合短期（如 5/15 周期）和长期（如 21/42 周期）的均线和形态支持力量。
3. **EMA Overextension (w_ema, 默认 15%)**: 惩罚均线过度偏离（如偏离 8ema > 3% 时减分），奖励回归均线的良好 Pullback 买点。
4. **ADX Momentum (w_adx, 默认 10%)**: 趋势强度过滤。只有 ADX 高于某一基线时，趋势才被认可，增强信号可信度。
5. **RVOL (Relative Volume)**: 不直接作为权重，而是作为单独过滤层，如果成交量急剧萎缩但出现突破信号，则降低评级或拒绝。

**Score Tier（综合分层）**:
最终合成 0 - 100 的 Score，分别进入以下四个级别（Tier）：
- **S 级** (≥ 90): 极高确定性的环境和形态。
- **A 级** (80-89): 良好买点。
- **B 级** (70-79): 可选机会。
- **C 级** (< 70): 不推荐交易，或是低质量信号。

### 2. 模式识别与策略推荐结构

依靠以上得分、长期/短期趋势状态（Regime）以及日内的多重均线排列，算法会自动推导：

- **Setup（交易形态）**: `Squeeze Breakout`, `Breakout`, `Pullback Buy`, `Strong Trend`, `Bottom Bounce` 等，并伴随信心星级（⭐⭐⭐ = Perfect Storm）。
- **Strategy Type（期权推荐）**: 给出最佳的建仓结构：
  - 高隐波、中性区间（HV/IV 对比）→ **Iron Condor**
  - 单边强突破或回踩突破 → **LONG CALL / LONG PUT**
  - 高 IV 但有单边方向 → **Credit Put Spread / Credit Call Spread**

### 3. Forward Expectancy Analysis (自带回测逻辑)

为验证 Tiers 和评分系统是否可靠，Scanner 自带了一套前瞻测试（Look-Forward Backtest）模块。核心解决了期权回测中的盈亏维度混淆问题。

**回测周期**: 14 bars (约两周) 和 30 bars (约一个月) 的收盘价涨幅。

**处理 IC（Iron Condor） 与方向性策略的区别（重要逻辑更新）**:
- **Call/Put (方向性交易)**：
  如果发出 LONG CALL 信号，那么 `trade_move = (+价格变动 %)`
  如果发出 LONG PUT 信号，那么 `trade_move = (-价格变动 %)`
  **14天/30天期望 Moves** 代表了单纯按照这一方向做期权的底仓真实涨跌幅（正代表盈利，负代表相反走势引发亏损）。

- **Iron Condor (非方向性交易)**：
  中性交易不需要方向涨幅，而是对“价格漂移幅度”敏感。
  在计算 IC 历史命中率时，我们检查价格波动的**绝对值**：`math.abs(move) ≤ 0.055`（例如30d内漂移小于 5.5% 算作 Win）。
  并且从 v3.2 开始，**IC 交易被严格从方向性 Tier 的平均收益计算中剔除**，防止它们无方向的绝对值计算拉高（或扭曲）了 S/A/B/C 级趋势投资者的 14d/30d EXPECTED MOVE 的真实收益平均数。

### 4. 动态 TP/SL 期望模拟器

在 TV 参数中，用户可以设置例如 `TP (Take Profit) = 2.0x ATR`, `SL (Stop Loss) = 1.0x ATR`。
算法将遍历过去的所有信号，检测：在 14d 或 30d 到达前，价格是否先触及了目标价(TP)或止损价(SL)。

最后在回测表中单列输出：
`TP2A/SL1A S(90+)`, `A(80+)`, `B(70+)`, `C(<70)` 的胜率、平均盈亏及触及止盈/止损的具体次数。
这为最终到 Web App 填写理想 `Entry` 和 `Stop Loss` 提供了具有统计学支撑的数据依据。

## 🎯 Pine Script 设置感知统一评分（OSS v2.6 新增）

当 TradingView Pine Script v3.2 已经通过 `s_identify()` 验证了方向性信号（如 `Perfect Storm = Conf 3`），说明 Regime 对齐已在前置流程中完成。若统一评分仍以 40% 权重强调 EV/Risk，会对本身 EV 适中（但信号极强）的推荐造成双重惩罚。

### 解决方案

在 `calculateUnifiedScore(candidate, category, regimeMode, ivRvRatio, opts)` 中：

```typescript
const hasPineSetup = opts?.setup
    && opts.setup !== ''
    && opts.setup !== 'Mixed'
    && opts.setup !== 'Other';
```

**权重切换**：

| 维度 | 默认权重 | Pine Script 有效设置时 |
|------|----------|----------------------|
| EV/Risk | **40%** | **35%** |
| POP | 20% | 20%（不变） |
| Regime 对齐 | **25%** | **30%** |
| 流动性 | 15% | 15%（不变） |

**触发条件**：
- `opts.setup` 非空、非 `'Mixed'`、非 `'Other'`
- 涵盖所有强信号：`Perfect Storm`、`Squeeze Breakout`、`Breakout`、`Strong Trend`、`Pullback Buy` 等

**调用方式**（`strategy-recommend.js`）：
```javascript
const { score, factors } = calculateUnifiedScore(
    rec, simCat, regime.mode, regime.ivRvRatio,
    { ...unifiedOpts, skew, creditSpreadType, setup: decodedSetup }
);
```
