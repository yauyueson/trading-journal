## 🎯 OSS评分系统概述

### Options Scoring System (OSS)

**版本**: 2.4 (Vega 纳入 LOQ/CSQ)

**v2.4 新增**:
- **Vega 效率 (LOQ)**：做多期权时引入 `vega/权利金` 的池内 Z-Score；IV 偏低时对高 vega 效率加分，IV 偏高时轻微扣分，避免买在 IV 极高且 vega 又大的合约。
- **Vega 惩罚 (CSQ)**：卖权时对 `vega/权利金` 的池内 Z-Score 施加温和惩罚，高 vega 合约分数略降（对波动率更敏感）。

**v2.3 已有**:
- **Hard Filters (候选池治理)**: 入池前移除噪音合约——minMid $0.15、minOpenInterest 200、maxSpreadPct 上限 12%
- **Bucketed Z-Scores (DTE 分桶归一化)**: Z-Score 在 DTE 同行组内计算，避免 7-DTE 和 45-DTE 合约在同一池内互相扭曲
- **True Expiration Breakeven**: BE 改用到期 strike-based 公式 `|K ± premium - S| / S`，替代旧的 delta 线性近似，彻底打击深 OTM 彩票合约

**v2.2 已有**:
- **Gamma/Theta Ratio (G/T)**: "Gamma 性价比"指标，衡量每单位 Theta 损耗获得的 Gamma 加速度
- **Breakeven Move %**: "回本难度"指标，DTE 归一化的现实性检验
- **Credit Spread EV**: 信用价差评分加入完整期望值维度
- LOQ 权重重新分配（Lambda 0.30, GammaEff 0.20, G/T 0.15, ThetaBurn -0.10, DeltaBonus 0.15, BE 0.10）
- Day Trade 权重更新（G/T 0.20, BE 0.05，日内弱化回本难度）
- G/T Soft Compression: 阈值 5，衰减率 0.1，防止极端值

**v2.1 已有**:
- Delta Bonus LERP: 线性插值奖励曲线，消除评分突变台阶
- Lambda Soft Compression: 对高杠杆进行对数级衰减，防止极端值污染评分
- Day Trade Mode: 支持日内模式，自动切换权重（侧重 Gamma，忽略 Theta）
- Theta Pain Cap: 惩罚封顶从 50 分调整为 10 分，平衡性更佳

**核心理念**: 
通过量化指标评估期权质量，避免主观判断和情绪化决策。

**两大评分系统**:
1. **LOQ** (Long Option Quality) - 买方评分
2. **CSQ** (Credit Spread Quality) - 卖方评分

**评分范围**: 0-100分
- **80-100**: 优秀机会
- **70-79**: 良好机会
- **60-69**: 一般机会
- **<60**: 不建议交易

## 📈 LOQ算法（买方评分）

### 1. 核心指标

#### Lambda (Λ) - 真实杠杆率

**定义**: 衡量期权的资本效率

**公式**:
```
Lambda = |Delta| × (Stock Price / Option Price)
```

**解释**:
- 高Lambda = 高杠杆，小资本控制大敞口
- 例: Delta=0.4, 股价=$620, 期权价=$7.36
  - Lambda = 0.4 × (620 / 7.36) = 33.7
  - 意味着$1期权价格变动相当于$33.7股票敞口

**理想范围**: 5-15
- <5: 杠杆不足，不如买股票
- 5-15: 黄金区间
- >20: 过度杠杆，触发**平滑压缩 (Soft Compression)**

#### Lambda Soft Compression (平滑压缩)

**目的**: 避免极低价格期权产生天文数字级的 Lambda 从而扭曲 Z-Score。

**公式**:
```
if (lambda <= 20):
  processed_lambda = lambda
else:
  processed_lambda = 20 + (lambda - 20) * 0.1
```

**效果**: Lambda=50 实际被压缩为 23，既保留了排名优势，又防止了数据爆炸。

**代码实现**:
```typescript
export function calculateLambda(
  delta: number, 
  stockPrice: number, 
  optionPrice: number
): number {
  if (optionPrice <= 0) return 0;
  return Math.abs(delta) * (stockPrice / optionPrice);
}
```

---

#### Gamma Efficiency (Γeff) - 爆发力

**定义**: 单位价格的Delta加速度

**公式**:
```
Gamma Efficiency = Gamma / Option Price
```

**解释**:
- 高Gamma Eff = Delta快速增长，有利方向移动时收益加速
- 例: Gamma=0.0123, 期权价=$7.36
  - Gamma Eff = 0.0123 / 7.36 = 0.00167
  - 股价每涨$1，Delta增加0.0123

**理想范围**: 0.01-0.05
- <0.01: Delta变化太慢
- 0.01-0.05: 黄金区间
- >0.05: 过度敏感，风险高

**代码实现**:
```typescript
export function calculateGammaEfficiency(
  gamma: number, 
  optionPrice: number
): number {
  if (optionPrice <= 0) return 0;
  return gamma / optionPrice;
}
```

---

#### Theta Burn (TB) - 时间衰减率

**定义**: 每日时间价值损失率

**公式**:
```
Theta Burn = |Theta| / Option Price
```

**解释**:
- 低Theta Burn = 每日损失少，适合持有
- 例: Theta=-0.0456, 期权价=$7.36
  - Theta Burn = 0.0456 / 7.36 = 0.0062 (0.62%/天)
  - 每天损失0.62%的期权价值

**理想范围**: 0-0.05
- <0.02: 优秀（<2%/天）
- 0.02-0.05: 可接受
- >0.05: 时间衰减过快

**代码实现**:
```typescript
export function calculateThetaBurn(
  theta: number, 
  optionPrice: number
): number {
  if (optionPrice <= 0) return 0;
  return Math.abs(theta) / optionPrice;
}
```

---

#### Theta Pain Curve - 指数型惩罚 (v2.2 新增)

**定义**: 对高时间衰减的非线性惩罚

**设计理念**:
- 安全区 (≤0.5%/天): 零惩罚，对 LEAPS 友好
- 超出安全区: 惩罚呈二次增长
- 封顶 50 分，防止极端值炸穿评分

**公式**:
```
if (thetaBurn <= 0.005):
  penalty = 0
else:
  excess = thetaBurn - 0.005
  penalty = min((excess × 100)² × 0.5, 10)
```

**示例**:
```
0.3%/天 → 0 (安全)
1.0%/天 → 0.125 分
3.0%/天 → 3.125 分
6.0%/天 → 10.000 分 (封顶)
```

**代码实现**:
```typescript
export function getThetaPenalty(thetaBurn: number): number {
  const SAFE_ZONE = 0.005; 
  
  if (thetaBurn <= SAFE_ZONE) {
    return 0;
  }
  
  const excess = thetaBurn - SAFE_ZONE;
  const penalty = Math.pow(excess * 100, 2) * 0.5;
  
  return Math.min(penalty, 10);
}
```

---

#### Gamma/Theta Ratio (G/T) - Gamma 性价比 (v2.2 新增)

**定义**: 衡量每单位 Theta 损耗获得的 Gamma 加速度

**公式**:
```
G/T = Gamma / |Theta|
```

**解释**:
- 高 G/T = Gamma 便宜，时间衰减换来的 Delta 加速多
- 低 G/T = Gamma 昂贵，每天付出的 Theta 换来的 Gamma 少
- 例: Gamma=0.02, Theta=-0.01
  - G/T = 0.02 / 0.01 = 2.0
  - 每损耗 $0.01 Theta，获得 0.02 的 Delta 加速

**理想范围**: 0.5-3.0
- <0.3: Gamma 过贵，不划算
- 0.5-3.0: 合理区间
- >5.0: 触发**平滑压缩 (Soft Compression)**

#### G/T Soft Compression (平滑压缩)

**目的**: 当 Theta 极小（如 LEAPS）时 G/T 可能爆炸，需要衰减。

**公式**:
```
if (|theta| < 0.001):
  G/T = gamma > 0 ? 5 : 0     // 封顶
else if (G/T <= 5):
  processed_GT = G/T
else:
  processed_GT = 5 + (G/T - 5) * 0.1
```

**效果**: G/T=10 被压缩为 5.5，保留排名优势但防止 Z-Score 爆炸。

**代码实现**:
```typescript
export function calculateGammaThetaRatio(gamma: number, theta: number): number {
    const absTheta = Math.abs(theta);
    if (absTheta < 0.001) return gamma > 0 ? 5 : 0;
    const raw = gamma / absTheta;
    const THRESHOLD = 5;
    const DECAY_RATE = 0.1;
    if (raw <= THRESHOLD) return raw;
    return THRESHOLD + (raw - THRESHOLD) * DECAY_RATE;
}
```

**与其他指标的关系**:
| 指标 | 衡量维度 | 回答的问题 |
|------|----------|-----------|
| Gamma Efficiency | Gamma / 期权价 | 每投入 $1 获得多少 Gamma？ |
| Theta Burn | \|Theta\| / 期权价 | 每天损失投资额的百分之几？ |
| **G/T Ratio** | **Gamma / \|Theta\|** | **每付出 $1 Theta 获得多少 Gamma？** |

三者共同构成完整的"Gamma 成本分析"：G/T 直接衡量 Gamma 和 Theta 之间的**性价比关系**，而非各自与价格的关系。

#### Breakeven Move % - 真实到期回本难度 (v2.3 改进)

**定义**: 到期时股价需要移动多少百分比，买方才能回本

**v2.3 改动**: 从 delta 线性近似改为 **strike-based 真实到期 breakeven**。

旧公式 `premium / (|Δ| × S)` 对深 OTM / 高 Gamma 区严重偏离——某些合约被误判"回本要求不高"，实际到期 breakeven 很远。新公式直接用 strike，精确无误。

**公式 (v2.3)**:
```
Call:  BE = K + premium     → Move% = |BE - S| / S
Put:   BE = K - premium     → Move% = |BE - S| / S

其中:
- K = 行权价 (strike)
- premium = (bid + ask) / 2
- S = 标的股价 (currentPrice)
```

**示例对比**:
```
SPY $600, Call K=610, mid=$3.50, delta=0.35:
  旧 (delta): 3.50 / (0.35 × 600) = 1.67%  ← 偏小
  新 (strike): |610+3.50-600| / 600 = 2.25%  ← 真实

SPY $600, Call K=650, mid=$0.50, delta=0.05:
  旧 (delta): 0.50 / (0.05 × 600) = 1.67%  ← 严重失真！
  新 (strike): |650+0.50-600| / 600 = 8.42%  ← 彩票合约现形

SPY $600, Put K=580, mid=$2.00:
  新 (strike): |580-2.00-600| / 600 = 3.67%
```

**DTE 归一化**:
不同到期日的期权，合理 Breakeven 不同。60 天期权允许更大的波动范围。

```
DTE Factor = sqrt(DTE / 30)
Adjusted BE = Breakeven Move / DTE Factor

示例:
  BE=5%, DTE=30 → Adjusted=5.0% (参考基准)
  BE=5%, DTE=60 → Adjusted=3.5% (60天有更多时间)
  BE=5%, DTE=7  → Adjusted=10.4% (7天内要涨5%很难)
```

**Penalty/Bonus 曲线 (LERP)**:
```
Adjusted BE ≤ 2%:    +0.5  (很容易达到)
Adjusted BE 2-5%:    lerp(+0.5, 0)
Adjusted BE 5-10%:   lerp(0, -1.0)
Adjusted BE 10-20%:  lerp(-1.0, -2.0)
Adjusted BE > 20%:   -2.0  (封顶，极不现实)
```

**代码实现 (v2.3)**:
```typescript
export function calculateBreakevenMove(
    strike: number, premium: number, stockPrice: number, optionType: 'Call' | 'Put'
): number {
    if (stockPrice <= 0) return 1;
    const breakeven = optionType === 'Call' ? strike + premium : strike - premium;
    return Math.abs(breakeven - stockPrice) / stockPrice;
}

export function getBreakevenPenalty(breakevenMove: number, dte: number): number {
    const dteFactor = dte > 0 ? Math.sqrt(dte / 30) : 1;
    const adjusted = breakevenMove / dteFactor;

    if (adjusted <= 0.02) return 0.5;
    if (adjusted <= 0.05) return lerp(adjusted, 0.02, 0.05, 0.5, 0);
    if (adjusted <= 0.10) return lerp(adjusted, 0.05, 0.10, 0, -1.0);
    if (adjusted <= 0.20) return lerp(adjusted, 0.10, 0.20, -1.0, -2.0);
    return -2.0;
}
```

**需要的字段**: strike K、mid premium、underlying price S、optionType — 链上全部具备。

**与 Delta Bonus 的区别**:
| 指标 | 衡量角度 | 输入 |
|------|----------|------|
| Delta Bonus | 期权的 moneyness 类别 | 仅 Delta |
| **Breakeven Move** | **到期时真实回本所需的股价变动** | **strike + premium + 股价 + DTE** |

Delta Bonus 回答"这个 Delta 好不好"，Breakeven Move 回答"这笔交易到期能回本吗"。两者互补。

#### Delta Bonus - ATM奖励

**定义**: 奖励ATM期权，惩罚彩票式期权

**规则 (LERP 线性插值)**:
为了避免 Delta 在 0.14 和 0.15 之间产生巨大的评分分水岭，我们使用线性插值：

- **|Δ| < 0.15**: -2.0 定值 (彩票惩罚)
- **|Δ| 0.15 - 0.30**: 从 -2.0 线性过渡到 -0.5
- **|Δ| 0.30 - 0.50**: 从 -0.5 线性过渡到 +1.0 (甜蜜区)
- **|Δ| 0.50 - 0.70**: 从 +1.0 线性过渡到 +0.5
- **|Δ| > 0.70**: 从 +0.5 线性过渡到 0 (深度 ITM)

**代码实现**:
```typescript
export function getDeltaBonus(delta: number): number {
  const absDelta = Math.abs(delta);
  const lerp = (x, x1, x2, y1, y2) => y1 + (y2 - y1) * ((x - x1) / (x2 - x1));

  if (absDelta < 0.15) return -2.0;
  if (absDelta < 0.30) return lerp(absDelta, 0.15, 0.30, -2.0, -0.5);
  if (absDelta < 0.50) return lerp(absDelta, 0.30, 0.50, -0.5, 1.0);
  if (absDelta < 0.70) return lerp(absDelta, 0.50, 0.70, 1.0, 0.5);
  return lerp(absDelta, 0.70, 1.0, 0.5, 0);
}
```

### 2. 候选池治理 — Hard Filters (v2.3 新增)

**问题**: 噪音合约（超便宜、低 OI、宽 spread）污染池的均值/方差，导致排名日间跳变并系统性偏向垃圾合约。

**解决**: 在进入 Z-Score 评分之前，用硬过滤器移除噪音：

```typescript
export const HARD_FILTER_DEFAULTS = {
    minMid: 0.15,            // mid < $0.15 的合约直接丢弃
    minOpenInterest: 200,    // OI < 200 的合约直接丢弃
    maxSpreadPctCeiling: 0.12, // spread% 硬上限 12%（即使用户传更宽也不超过）
};
```

**作用**: 扫描器 (`scan-options`)、前端评分 (`scoreOptionsChain`)、策略推荐器 (`strategy-recommend`) 统一应用，确保三个入口的候选池一致。

### 3. Z-Score标准化 — DTE 分桶归一化 (v2.3 改进)

**问题**: 旧版 Z-Score 在全池内计算。7-DTE 的极端 Gamma/Price 与 45-DTE 在同一池比较，扭曲 Z-Score 分布。

**解决**: 按 DTE 分桶计算 Z-Score，每个桶内独立归一化。同行比同行。

**DTE 桶**:
```typescript
export const DTE_BUCKETS = [
    { label: '0-14',   min: 0,   max: 14  },
    { label: '15-30',  min: 15,  max: 30  },
    { label: '31-60',  min: 31,  max: 60  },
    { label: '61-120', min: 61,  max: 120 },
    { label: '121+',   min: 121, max: Infinity },
];

export const MIN_BUCKET_SIZE = 3; // 桶内不足 3 个则回退到全池统计
```

**公式**:
```
对每个 DTE 桶 b:
  μ_b = mean(values in bucket b)
  σ_b = std(values in bucket b)

Z_i = (x_i - μ_b) / σ_b    // 使用所属桶的统计量
      若桶内 < 3 个，退回 (x_i - μ_pool) / σ_pool
```

**优雅退化**:
- 窄 DTE 扫描（如 30-45）→ 全部落入同一桶 → 等价于旧行为
- 小结果集 → 桶内不足 3 个 → 自动回退到全池统计
- 宽 DTE 扫描（如 5-90）→ 分桶生效，7-DTE 和 45-DTE 各自组内比较

**代码实现**:
```typescript
export function normalizeToZScoresByBucket(
    values: number[], dtes: number[], minBucketSize: number = MIN_BUCKET_SIZE
): number[] {
    const n = values.length;
    if (n < 2) return values.map(() => 0);

    // 全池统计量（fallback）
    const poolMean = values.reduce((s, v) => s + v, 0) / n;
    const poolStd = Math.sqrt(values.reduce((s, v) => s + (v - poolMean) ** 2, 0) / n) || 1;

    // 分配桶 → 计算桶内统计量 → 若桶够大则用桶内、否则用全池
    // ... (详见 oss-core.ts)
}
```

**旧版 `normalizeToZScores` 保留不变**，供 `calculateSingleLOQ` 等无 DTE 数组的场景使用。

**示例**:
```
原始Lambda: [5.2, 8.7, 12.3, 15.1, 18.9]
均值: 12.04
标准差: 5.12
Z-Scores: [-1.34, -0.65, 0.05, 0.60, 1.34]
```

### 3. LOQ加权计算

**权重配置 (Standard Mode, v2.2)**:
```typescript
const LOQ_WEIGHTS = {
  lambda: 0.30,           // 杠杆率
  gammaEff: 0.20,         // 爆发力
  gammaThetaRatio: 0.15,  // Gamma 性价比
  thetaBurn: -0.10,       // 时间衰减（负权重）
  deltaBonus: 0.15,       // 线性插值奖励
  breakevenPenalty: 0.10  // 回本难度 (v2.2 新增)
};
```

**权重配置 (Day Trade Mode, v2.2)**:
*当 DTE ≤ 5 且开启日内模式时触发*
```typescript
const DT_WEIGHTS = {
  lambda: 0.30,
  gammaEff: 0.35,         // 强化爆发力要求
  gammaThetaRatio: 0.20,  // 日内更重视 Gamma 成本效率
  thetaBurn: -0.05,       // 弱化时间衰减（日内持有影响小）
  breakevenPenalty: 0.05, // 日内弱化回本难度（本来就是短线）
  penaltyMult: 0.2        // Theta Pain 惩罚减弱 80%
};
```

**DTE 连续权重 (v2.2)**  
不再用「DTE≤5 用 DT / 否则用 Standard」的二元切换，改为按 DTE 平滑过渡，避免 6 DTE 与 5 DTE 分数跳变：

- **DTE ≤ 5**：完全使用 DT 权重  
- **DTE 5–15**：在 DT 与 Standard 之间线性插值（t = (dte - 5) / 10）  
- **DTE ≥ 15**：完全使用 Standard 权重  

`calculateLOQRaw` 在传入 `dte` 时使用 `getLOQWeightsForDTE(dte)`；未传 `dte` 时仍用 `isDayTrade` 布尔逻辑以保持兼容。

**公式** (v2.4 含 Vega):
```
LOQ_Raw = 0.30×z(Λ) + 0.20×z(Γeff) + 0.15×z(G/T) - 0.10×z(TB)
        + 0.15×ΔBonus + 0.10×BEPenalty
        + IV_Adj - ThetaPainPenalty + VegaBonus

其中:
- z(Λ): Lambda的Z-Score
- z(Γeff): Gamma Efficiency的Z-Score
- z(G/T): Gamma/Theta Ratio的Z-Score
- z(TB): Theta Burn的Z-Score
- ΔBonus: Delta奖励/惩罚 (LERP)
- BEPenalty: Breakeven Move 回本难度惩罚/奖励 (LERP, DTE归一化) (v2.2)
- IV_Adj: IV期限结构调整（使用 Sigmoid 平滑过渡）
- ThetaPainPenalty: 指数型 Theta 惩罚（对末日轮的额外惩罚）
- VegaBonus (v2.4): Vega 效率 z(vega/权利金) 的 regime 微调
  - IV_Adj > 0（IV 偏低/contango）: +0.05×z(VegaEff)，从 IV 上升中获利时偏好高 vega
  - IV_Adj < 0（IV 偏高）: -0.03×z(VegaEff)，避免买在 IV 极高且 vega 又大的合约
  - IV_Adj = 0: 0
```

**代码实现** (v2.4):
```typescript
// 常量: LOQ_VEGA_EFF_WEIGHT_POS = 0.05, LOQ_VEGA_EFF_WEIGHT_NEG = -0.03
export function calculateLOQRaw(
  zLambda: number,
  zGammaEff: number,
  zThetaBurn: number,
  ivAdjustment: number,
  deltaBonus: number = 0,
  thetaBurn: number = 0,
  isDayTrade: boolean = false,
  zGammaThetaRatio: number = 0,
  breakevenPenalty: number = 0,
  dte: number | null = null,
  vegaZ: number = 0  // z(vega/权利金), 池内 DTE 分桶 Z-Score
): number {
  const thetaPenalty = getThetaPenalty(thetaBurn);
  const vegaWeight = ivAdjustment > 0 ? 0.05 : (ivAdjustment < 0 ? -0.03 : 0);
  const vegaBonus = vegaWeight * vegaZ;
  // ... 权重 w 由 getLOQWeightsForDTE(dte) 或 isDayTrade 决定
  return (
    w.lambda * zLambda + ... + ivAdjustment
    - thetaPenalty * w.penaltyMult + vegaBonus
  );
}
```

```
Clamped to [0, 100]
```

- 映射到 [0, 100]，中位数50分
- Z-Score=0 → 50分
- Z-Score=+2 → 75分
- Z-Score=+4 → 100分

**代码实现**:
```typescript
export function normalizeScoreTo100(rawScore: number): number {
```

## 📉 CSQ算法（卖方评分）

### 1. 核心指标

#### POP (Probability of Profit)

**定义**: 期权到期时盈利的概率

**公式**:
```
POP = 1 - |Delta|
```

**解释**:
- Delta近似为ITM概率
- POP = OTM概率（卖方盈利）
- 例: Delta=0.30 → POP=0.70 (70%盈利概率)

**代码实现**:
```typescript
export function calculatePOP(delta: number): number {
  return 1 - Math.abs(delta);
}
```

---

#### Seller's Edge - 卖方优势

**定义**: 期望收益

**公式**:
```
Edge = POP × Premium Received
```

**解释**:
- 结合概率和收益的期望值
- 例: POP=0.70, Premium=$2.50
  - Edge = 0.70 × 2.50 = $1.75
  - 期望每份合约赚$1.75

**代码实现**:
```typescript
export function calculateSellerEdge(pop: number, premium: number): number {
  return pop * premium;
}
```

---

#### Spread Percentage - 流动性

**定义**: 买卖价差占比

**公式**:
```
Spread% = (Ask - Bid) / Mid
```

**解释**:
- 低Spread = 高流动性，易成交
- 例: Bid=$2.45, Ask=$2.55
  - Mid = $2.50
  - Spread% = 0.10 / 2.50 = 4%

**理想范围**: <10%
- <5%: 优秀流动性
- 5-10%: 可接受
- >10%: 流动性差

**代码实现**:
```typescript
export function calculateSpreadPct(bid: number, ask: number): number {
  const mid = (bid + ask) / 2;
  if (mid <= 0) return 1; // 100% = 无流动性
  return (ask - bid) / mid;
}
```

### 2. CSQ加权计算

**权重配置**:
```typescript
const CSQ_WEIGHTS = {
  edge: 0.50,      // 卖方优势（最重要）
  pop: 0.30,       // 盈利概率
  spread: -0.20    // 流动性（负权重，低spread更好）
};
```

**公式** (v2.4 含 Vega 惩罚):
```
CSQ_Raw = 0.50×z(Edge) + 0.30×z(POP) - 0.20×z(Spread) + IV_Adj + VegaPenalty

其中 VegaPenalty (v2.4): -0.05×z(vega/权利金)，卖权时高 vega 对波动率更敏感，温和降分。
```

**代码实现** (v2.4):
```typescript
// 常量: CSQ_VEGA_PENALTY_WEIGHT = -0.05
export function calculateCSQRaw(
  zEdge: number,
  zPOP: number,
  zSpread: number,
  ivAdjustment: number,
  vegaPenalty: number = 0  // 通常为 -0.05 × z(vega/权利金)
): number {
  return (
    CSQ_WEIGHTS.edge * zEdge +
    CSQ_WEIGHTS.pop * zPOP +
    CSQ_WEIGHTS.spread * zSpread +
    ivAdjustment +
    vegaPenalty
  );
}
```

## 🌡️ IV期限结构分析

### 1. 4-Card Method

**目的**: 判断市场波动率环境

**方法**: 比较30天和90天ATM IV

**步骤**:
1. 找到30天到期的ATM Call和Put
2. 平均得到IV_30
3. 找到90天到期的ATM Call和Put
4. 平均得到IV_90
5. 计算比率: IV_Ratio = IV_30 / IV_90

**代码实现**:
```typescript
function getATMIV(
  chain: OptionData[],
  currentPrice: number,
  targetDTE: number,
  tolerance: number = 10
): number | null {
  // 1. 筛选目标DTE附近的Call
  const candidates = chain.filter(
    opt => opt.type === 'Call' && Math.abs(opt.dte - targetDTE) <= tolerance
  );
  
  if (candidates.length < 2) return null;
  
  // 2. 按行权价排序
  candidates.sort((a, b) => a.strike - b.strike);
  
  // 3. 找到夹住当前价格的两个行权价
  for (let i = 0; i < candidates.length - 1; i++) {
    if (candidates[i].strike <= currentPrice && 
        candidates[i + 1].strike >= currentPrice) {
      return (candidates[i].iv + candidates[i + 1].iv) / 2;
    }
  }
  
  // 4. 降级：使用最接近的行权价
  const closest = candidates.reduce((prev, curr) =>
    Math.abs(curr.strike - currentPrice) < Math.abs(prev.strike - currentPrice) 
      ? curr : prev
  );
  return closest.iv;
}

export function calculateIVRatio(
  chain: OptionData[], 
  currentPrice: number
): IVTermResult {
  const iv30 = getATMIV(chain, currentPrice, 30);
  const iv90 = getATMIV(chain, currentPrice, 90);
  
  if (!iv30 || !iv90 || iv90 === 0) {
    return { ivRatio: 1.0, iv30, iv90, status: 'neutral' };
  }
  
  const ratio = iv30 / iv90;
  
  let status: 'contango' | 'neutral' | 'backwardation';
  if (ratio < 0.95) {
    status = 'contango';      // 近期IV低，适合买入
  } else if (ratio > 1.05) {
    status = 'backwardation';  // 近期IV高，适合卖出
  } else {
    status = 'neutral';        // 正常状态
  }
  
  return { ivRatio: ratio, iv30, iv90, status };
}
```

### 2. IV调整规则 (v2.2 Sigmoid 平滑过渡)

**设计理念**:
- 市场情绪在"冷静"和"恐慌"之间突变
- 使用 Sigmoid 函数模拟这种相变
- k=12 提供平滑但明确的过渡
- x0=1.10 作为临界点

**IV Risk Factor 公式**:
```
riskFactor = 0.9 + sigmoid(ratio, k=12, x0=1.10) × 0.4

返回值:
- ~0.9 = 安全 (Contango, ratio < 1.0)
- ~1.0 = 中性 (ratio ≈ 1.05)
- ~1.3 = 危险 (Backwardation, ratio > 1.15)
```

**买方（LOQ）调整**:
```
IV_Adj = (1 - riskFactor) × 5

- riskFactor=0.9 → +0.5 (Contango 奖励)
- riskFactor=1.0 → 0 (中性)
- riskFactor=1.3 → -1.5 (Backwardation 惩罚)
```

**卖方（CSQ）调整**:
```
IV_Adj = (riskFactor - 1) × 5

- riskFactor=0.9 → -0.5 (Contango 惩罚)
- riskFactor=1.0 → 0 (中性)
- riskFactor=1.3 → +1.5 (Backwardation 奖励，卖高IV)
```

**代码实现**:
```typescript
export function getIVRiskFactor(ratio: number): number {
  const k = 12;     // Steepness
  const x0 = 1.10;  // Critical point
  
  const raw = 1 / (1 + Math.exp(-k * (ratio - x0)));
  
  return 0.9 + raw * 0.4;
}

export function getIVAdjustment(ivRatio: number, strategy: Strategy): number {
  const riskFactor = getIVRiskFactor(ivRatio);
  
  if (strategy === 'long') {
    return (1 - riskFactor) * 5;
  } else {
    return (riskFactor - 1) * 5;
  }
}
```

### 3. IV Rank 纵向对比 (v2.2)

**目的**: 期限结构（IV30/IV90）只反映「近期 vs 远期」相对关系，不反映当前 IV 在**历史**中的位置。IV Rank 回答：当前 IV 在过去 252 个交易日中处于什么分位？

**定义**:
- **IV Rank** = (当前 IV30 − 52 周最低 IV30) / (52 周最高 IV30 − 52 周最低 IV30)，取值 [0, 1]
- **IV Percentile** = 过去 252 天中有多少天的 IV30 低于当前值，比例 [0, 1]

**数据来源**: 表 `ticker_iv_snapshots`。每次 Scanner 或 Strategy Recommender 请求会 upsert 当日 (ticker, recorded_date, iv30, iv90)。历史随使用逐步积累；无历史时 IV Rank 调整为 0。

**评分调整** (与期限结构调整**叠加**):
```
若 ivRank == null: 不调整
买方 (long):
  ivRank < 0.3  → +0.5  (IV 便宜，适合买)
  ivRank > 0.7  → -0.5  (IV 贵，不适合买)
卖方 (short):
  ivRank < 0.3  → -0.3  (IV 便宜，不适合卖)
  ivRank > 0.7  → +0.5  (IV 贵，适合卖)
```

**API**: `GET /api/iv-rank?ticker=QQQ` 返回 `{ ivRank, ivPercentile, currentIv30, minIv, maxIv, sampleDays }`。

### 4. 卖方价差 (Credit Spread) 特殊核算

对于卖方信用价差（Credit Spread），系统采用“平仓成本（Cost to Close）”逻辑：

**平仓成本 (Cost to Close)**:
```
Cost to Close = Short Leg Price - Long Leg Price
(始终保持为正值，反映当前平仓所需支付的净权利金)
```

**未实现 P&L**:
```
Unrealized P&L = (Entry Credit - Current Cost to Close) × Quantity × 100
```

**逻辑解释**:
- 开仓时获得 $1.00 (Entry Credit)
- 当前平仓需支付 $0.80 (Cost to Close) → 盈利 $0.20
- 当前平仓需支付 $1.20 (Cost to Close) → 亏损 $0.20

**代码实现 (PositionCard.tsx)**:
```typescript
if (isCreditStrategy) {
    // 信用价差：平仓成本 = 空头价格 - 多头价格
    netPrice = shortPrice - longPrice;
    unrealizedPnL = (entryPrice - netPrice) * quantity * 100;
} else {
    // 借方/买方：持仓价值 = 现价 - 成本
    unrealizedPnL = (currentPrice - avgCost) * currentQty * 100;
}
```

## 📊 组合评分算法 (Spread Scoring)

系统对价差策略（Spreads）采用综合特征评分，确保 Portfolio 与 Strategy Recommender 评分一致。

### 1. 信用价差评分 (Credit Spread Score - CSQ+, v2.2 EV-Enhanced)

**核心权重** (v2.2):
- **EV (30%)**: 完整期望值 = POP × Credit - (1-POP) × MaxRisk。综合风险与收益的核心指标。 *(v2.2 新增)*
- **ROI (25%)**: 权利金 / 最大风险。25% ROI 达到满分。
- **POP (25%)**: 盈利概率 (1 - |Short Delta|)。
- **Distance (20%)**: 行权价距离股价的深度。10% OTM 达到满分。

**EV 评分映射**:
```
evRatio = EV / Credit    // 期望收益占权利金的比例
scoreEV = clamp(50 + evRatio × 100, 0, 100)

示例:
  evRatio = +0.50 → 100 (优秀：期望保留50%权利金)
  evRatio = +0.25 → 75  (良好)
  evRatio =  0.00 → 50  (盈亏平衡)
  evRatio = -0.25 → 25  (负EV)
  evRatio = -0.50 → 0   (严重负EV)
```

**为什么需要 EV + ROI + POP 三维？**
- ROI 只看上行：25% ROI 可能来自高概率小赢或低概率大赢
- POP 只看概率：90% POP 但赚 $0.10 赔 $4.90 实际 EV 为负
- **EV 整合两者**：唯一回答"这笔交易数学上是否值得"的指标

**代码逻辑** (v2.2):
```typescript
const ev = calculateExpectedValue(pop, credit, maxRisk);
const evRatio = credit > 0 ? ev / credit : 0;
const scoreEV = Math.max(0, Math.min(100, 50 + evRatio * 100));

const scoreROI = Math.min(roi * 4, 100); 
const scorePOP = pop * 100;
const scoreDistance = Math.min(distance * 1000, 100); 

finalScore = Math.round(0.30 * scoreEV + 0.25 * scoreROI + 0.25 * scorePOP + 0.20 * scoreDistance);
```

### 2. 借方价差评分 (Debit Spread Score - LOQ+)

**核心权重**:
- **Lambda (40%)**: 组合杠杆率。
- **Risk/Reward (35%)**: 盈亏比。1:3 R:R 达到满分。
- **Delta Bonus (25%)**: 组合 Delta 对方向性的奖励。

**代码逻辑**:
```typescript
const lambdaScore = Math.min((compLambda / 20) * 100, 100); 
const rrScore = Math.min((riskReward / 3) * 100, 100);      
const deltaScore = 50 + deltaBonus * 12.5;

finalScore = Math.round(0.4 * lambdaScore + 0.35 * rrScore + 0.25 * deltaScore);
```
