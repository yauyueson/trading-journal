# 止损 / 目标价 提醒 — 实现方案

> 最后更新: 2026年2月8日
>
> 目标：当某一笔 **Active** 持仓的当前价格触及 **止损** 或 **目标价** 时，自动发送 Discord 推送提醒（不依赖用户是否打开 App）。
>
> **当前状态**：✅ 已实现并上线，使用 Discord Webhook + cron-job.org 外部定时触发。

---

## 0. 系统架构（当前实现）

```
cron-job.org (每 15 分钟 GET)
    ↓
/api/check-alerts?secret=CRON_SECRET
    ↓
1. 鉴权（CRON_SECRET）
2. Supabase REST API 查询 Active 持仓 + 交易记录
3. 逐笔调用 /api/option-price 获取当前价
4. 按止损/目标价规则判断是否触及
5. 触及 → Discord Webhook POST（Embed 格式）
```

**止损规则**：Debit（买方）入场价 × 0.5 或 × 0.75（有部分止盈）；Credit（卖方）入场价 × 1.5。  
**技术实现**：`api/check-alerts.js` 使用 Supabase REST API（fetch），不依赖 `@supabase/supabase-js`；鉴权通过 `?secret=` 或 `Authorization: Bearer`；定时由 cron-job.org 每 15 分钟触发。

---

## 1. 整体思路

- **触发判定必须在服务端、定时执行**：只有后端定时跑任务，才能在你没打开网页时也判断「价格到了」并发短信。
- **流程**：定时任务 → 拉取所有 Active 持仓 → 逐笔拉取当前价（CBOE/option-price）→ 与止损/目标价比较 → 若触及则调短信接口 → 可选：记「已提醒」防重复轰炸。

下面按「需要补的数据与接口」「短信服务选型」「后端任务与 API 设计」「安全与成本」四块说明如何做到。

## 2. 当前数据与需补齐的部分

### 2.1 已有

| 数据 | 来源 | 说明 |
|------|------|------|
| Active 持仓列表 | Supabase `positions`（status=active） | 含 ticker, strike, type, expiration, legs（价差）, entry 成本等 |
| 目标价 | `positions.target_price` | 数字，可选 |
| 当前价（仅当用户刷新时） | `positions.current_price` | 前端刷新后写入，不是实时的 |

### 2.2 止损在 App 里是怎么算的（PositionCard）

- **Credit 策略**（卖期权）：止损价 = 入场价 × 1.5（当前价 ≥ 该值 → Hit Stop）。
- **Debit 策略**（买期权）：止损价 = 入场价 × 0.5（未部分止盈）或 × 0.75（已部分止盈）。

也就是说：**止损目前是「按规则算出来的」，没有单独存一个 `stop_price` 字段**。  
要做短信提醒，有两种做法：

- **方案 A（推荐）**：在库里增加 `stop_price`（可选），后台用「有则用，无则按上面规则算」，这样以后你也可以支持「自定义止损价」。
- **方案 B**：不在库里加字段，后台完全按当前前端的同一套公式算（Credit 1.5× / Debit 0.5× 或 0.75×）。

两种都能实现「到达止损发短信」；A 更利于后续扩展。

### 2.3 需要「当前价」从哪来

- 定时任务里**不能依赖** `positions.current_price`（用户不刷新就是旧的）。
- 需要**按持仓调用你现有的 `/api/option-price`**（或等价的 CBOE 拉取逻辑）得到**当前 mid/ last 价**，再和止损价、目标价比较。  
  价差仓位：可以按「short leg 价 - long leg 价」得到当前组合价，再和止损/目标比较。

## 3. 通知渠道选型

| 方案 | 说明 | 成本 |
|------|------|------|
| **Discord Webhook** | 发到 Discord 频道/私信，手机装 Discord 即可收推送 | **免费** |
| **Twilio 短信** | 发到手机号 | 按条付费 |
| **邮件** | Nodemailer / SendGrid 等 | 免费额度通常够用 |

**推荐先用 Discord**：零成本、配置简单、手机端有推送。

---

## 3.1 使用 Discord 发提醒（推荐）

### 第一步：建一个 Discord 服务器 / 频道

1. 打开 [Discord](https://discord.com) 并登录（没有就注册）。
2. 左侧点 **+** 新建服务器，选「仅供我和我的朋友使用」即可，起个名（如 `Trading Alerts`）。
3. 在服务器里建一个文字频道，例如 `#alerts`，专门用来收提醒。

### 第二步：创建 Webhook（拿到 URL）

1. 在 **#alerts** 频道名上右键 → **编辑频道**（或 Channel Settings）。
2. 左侧选 **集成**（Integrations）→ **Webhook** → **新建 Webhook**。
3. 给 Webhook 起个名字（如 `Trading Journal`），可选头像。
4. 点 **复制 Webhook URL**，得到类似：
   ```text
   https://discord.com/api/webhooks/1234567890123456789/abcdefghijk...
   ```
5. **妥善保存**：这个 URL 相当于密码，谁拿到谁就能往这个频道发消息。不要提交到 Git、不要写在前端代码里。

### 第三步：在 Vercel 里配置

在 Vercel 项目 **Settings → Environment Variables** 里新增：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `DISCORD_WEBHOOK_URL` | 你复制的 Webhook URL | 提醒会发到这个频道 |

部署后，你的 `api/check-alerts.js` 里用这个环境变量发请求即可。

### 第四步：后端如何发一条消息到 Discord

Discord Webhook 就是一个 **HTTP POST**，无需 SDK。示例：

```javascript
// 在 check-alerts 里，当检测到触及止损或目标时：
const webhookUrl = process.env.DISCORD_WEBHOOK_URL;
if (!webhookUrl) return;

const message = {
  content: null,
  embeds: [{
    title: '🛑 触及止损',
    description: `${ticker} ${strike} ${type} · 当前价 $${currentPrice} 已触及止损 $${stopPrice}`,
    color: 0xef4444,  // 红色
    footer: { text: 'Trading Journal' },
    timestamp: new Date().toISOString()
  }]
};

// 若只想发纯文字，可以简化为：
// const message = { content: `🛑 触及止损: ${ticker} ${strike}${type} @ $${currentPrice}` };

await fetch(webhookUrl, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(message)
});
```

**目标价触及**时同理，把 `title` 改成 `🎯 触及目标价`，`color` 改成绿色 `0x22c55e` 即可。

### 第五步：在手机上收提醒

- 手机安装 **Discord App**，登录同一账号，加入上面建的服务器。
- 在 **用户设置 → 通知** 里打开该服务器的通知（或只打开 #alerts 频道的通知）。
- 之后只要 Webhook 发消息到 #alerts，你手机就会收到 Discord 推送。

## 3.1.1 如何让它自动发（定时跑）

提醒要「自动」发，必须有一个**定时任务**每隔一段时间调用「检查 + 发 Discord」的 API。本项目已提供：

- **API**：`/api/check-alerts`（见仓库内 `api/check-alerts.js`）  
  会：拉取所有 Active 持仓 → 逐笔取当前价 → 判断是否触及止损/目标价 → 触及则发 Discord。

### 定时触发方案：cron-job.org（已上线）

> ⚠️ **Vercel Cron 不可用**：Vercel Hobby（免费）计划仅支持**每日一次**的 Cron。`*/15 * * * *`（每 15 分钟）等高频配置会导致 Vercel 部署直接失败。因此 `vercel.json` 中**不能包含 crons 配置**。

当前使用 **[cron-job.org](https://cron-job.org)**（免费外部 cron 服务）：

1. 注册 cron-job.org 账号
2. 新建 Cron Job：
   - **URL**：`https://trading-journal-yuchen.vercel.app/api/check-alerts?secret=你的CRON_SECRET`
   - **方法**：GET
   - **间隔**：每 15 分钟（或自定义）
3. 在 cron-job.org 的 **History** 页面可查看执行记录（200 = 正常，401 = secret 错误，404 = 函数未部署）

### Vercel 环境变量配置

在 Vercel 项目 Settings → Environment Variables 中设置：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `CRON_SECRET` | 自定义随机字符串 | check-alerts 鉴权密钥，不要泄露 |
| `DISCORD_WEBHOOK_URL` | Discord Webhook URL | 提醒发送的目标频道 |

Supabase 变量（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`）Vercel 会自动注入给 Serverless 函数。

### 技术实现细节

- `check-alerts.js` **不使用** `@supabase/supabase-js` SDK：直接用 `fetch` 调 Supabase REST API（PostgREST）。原因：Vercel Serverless 对 ESM `import` 外部 npm 包有兼容性问题，其他 API 文件均不使用 `import`。
- 当前价通过内部调用 `/api/option-price` 获取（`VERCEL_URL` 由 Vercel 自动注入）。

### Discord 小结

| 项目 | 说明 |
|------|------|
| 成本 | 完全免费 |
| 配置 | 建频道 → 建 Webhook → 复制 URL → 填到 Vercel 环境变量 |

## 3.2 短信方案（Twilio，付费）

常见做法：用第三方「发短信 API」，你的后端只负责「判断该发了」然后调 API。

| 方案 | 说明 | 成本（约） |
|------|------|------------|
| **Twilio** | 最常用，文档多、支持多国 | 按条计费，美国约 $0.0079/条 |
| **AWS SNS** | 和 AWS 集成简单 | 按条计费，很便宜 |

流程：注册 Twilio → 拿到 Account SID、Auth Token、发信号码 → 在 Vercel 里配环境变量 → 在 check-alerts 里调 Twilio API 发短信。  
**中国大陆手机号**接收短信有合规/运营商限制；美国等地区号码用 Twilio 较简单。

## 4. 后端：定时任务 + 「检查并发短信」API

### 4.1 谁在定时跑？

- ~~**Vercel Cron**~~：Hobby 计划不支持高频 Cron（仅允许每日一次），高频配置会导致部署失败。**已弃用。**
- ✅ **外部 Cron 服务**（当前方案）：使用 [cron-job.org](https://cron-job.org)（免费），每 15 分钟 GET 请求 `https://trading-journal-yuchen.vercel.app/api/check-alerts?secret=你的CRON_SECRET`。

### 4.2 建议的 API：`/api/check-alerts`

职责：

1. **鉴权**：用 Query 或 Header 里的 `secret` 与 `VERCEL_CRON_SECRET`（或你自己设的 `ALERT_CRON_SECRET`）比对，避免被随便调用。
2. **拉取 Active 持仓**：从 Supabase 查 `status = 'active'` 的 positions（可只查需要提醒的：有 `target_price` 或会算 stop_price 的）。
3. **逐笔查当前价**：
   - 单腿：调你现有 `option-price` 逻辑（同项目内可直接 require 或 fetch 内部 URL）。
   - 价差：按 legs 调两次 option-price，算出「当前组合价」。
4. **算止损价**：  
   - 若 DB 有 `stop_price` 就用；  
   - 否则按当前逻辑：Credit 用 entry×1.5，Debit 用 entry×0.5 或 0.75（是否部分止盈可从 transactions 判断）。
5. **判断是否触及**：
   - 止损：Credit 当前价 ≥ 止损价；Debit 当前价 ≤ 止损价。
   - 目标：`target_price` 存在且（Debit 当前价 ≥ target，Credit 当前价 ≤ target，依你约定）。
6. **发提醒**：若触及，按你配置的渠道发送。**Discord**：`POST` 到 `DISCORD_WEBHOOK_URL`（见上文 3.1）；**短信**：调 Twilio 发到该用户手机号。
7. **防重复**（可选）：在 `positions` 加字段如 `alert_stop_sent_at` / `alert_target_sent_at`，同一笔持仓同类型只发一次；或当天只发一次，视你需求。

**Discord**：只需在 Vercel 配 `DISCORD_WEBHOOK_URL`，所有提醒发到同一频道；多用户可每人一个 Webhook URL 存 Supabase。  
**短信**：单用户可在环境变量写死 `ALERT_PHONE`；多用户在 Supabase 的 profiles 加 `phone`，按 position 所属 user 取号。

## 5. 实现清单（如何做到）

按顺序做即可实现「到达止损或目标发 Discord / 短信提醒」：

| 步骤 | 做什么 |
|------|--------|
| 1 | 决定止损是否要「可配置」：若要，在 `positions` 加 `stop_price`（nullable）；否则沿用现有公式。 |
| 2 | **Discord**：建服务器与频道 → 建 Webhook → 复制 URL → 在 Vercel 配 `DISCORD_WEBHOOK_URL`。或 **短信**：注册 Twilio，在 Vercel 配 `TWILIO_*`、`ALERT_PHONE`。 |
| 3 | 新建 `api/check-alerts.js`：鉴权 → 查 Active → 对每条持仓取当前价（内部调 option-price 或 CBOE）→ 算止损/目标是否触及 → 触及则按配置发 Discord（POST webhook）或 Twilio 短信；可选写回 `alert_*_sent_at`。 |
| 4 | 配定时触发：Vercel Cron 的 `vercel.json` 的 `crons`，或外部 cron 调 `GET /api/check-alerts?secret=xxx`。 |
| 5 | （可选）多用户：Discord 可为每人建一个 Webhook URL 存库；短信在 Supabase 的 profiles 加 `phone`，按 user 取号。 |

这样就不依赖你是否打开 App：**只要定时任务跑到了、发现价格触及止损或目标，就会发 Discord/短信**。

## 6. 安全与成本

- **鉴权**：`/api/check-alerts` 必须用 secret 校验，且不要暴露在前端。  
- **手机号**：不要打日志、不要进前端；只放在服务端环境变量或 Supabase 受 RLS 保护的列里。  
- **成本**：Twilio 按条计费，例如 15 分钟跑一次、每次最多发 N 条，可估算月成本；Vercel 免费额度一般够跑 cron。  
- **限流**：同一持仓同类型提醒可「24 小时内只发一次」或「只发一次直到你关闭/平仓」，避免价格在边界来回时短信轰炸。

---

## 7. 小结

- **做到「到达止损或目标就发提醒」**需要：**服务端定时任务 + 当前价获取（option-price/CBOE）+ 止损/目标判断 + 通知渠道（Discord Webhook 或 Twilio 短信）**。  
- 你现有结构已经具备：Active 列表、目标价、option-price、Supabase；补上「定时调用检查逻辑 + 发 Discord/短信」即可。  
- **推荐先用 Discord**：免费、配置快，手机装 Discord 即可收推送；需要短信再加 Twilio。
