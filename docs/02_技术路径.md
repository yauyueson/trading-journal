### OSS 评分架构（单点事实）

| 层级 | 文件 | 职责 |
|------|------|------|
| **规范源** | `src/lib/oss-core.ts` | LOQ/CSQ/Delta Bonus/Theta 惩罚/Lambda 压缩/Z-Score/价差评分；v2.4 Vega；LERP、Sigmoid、边缘防护 |
| **前端复用** | `src/lib/scoring.ts` | 从 oss-core re-export；`scoreOptionsChain`、IV 期限结构 `calculateIVRatio` |
| **API 镜像** | `api/_shared/scoring.cjs` | 与 oss-core 逻辑同步的 JS 实现，供 scan-options、strategy-recommend 引用；含跨策略统一评分 |

**原则**：不在此三处以外重复实现评分公式，保证扫描器与持仓卡片分数一致。

### 技术选择理由

| 技术 | 选择理由 |
|------|----------|
| React + TypeScript | 组件化、类型安全、生态成熟 |
| Vite | 极快开发服务器、现代化构建 |
| Tailwind CSS | 快速 styling，dark mode 友好 |
| Supabase | 免费 tier 够用，PostgreSQL 可靠，实时同步 |

| **期权数据** | Polygon.io（主）：实时 + Greeks + IV，仅请求所需 DTE/行权 + 1 分钟缓存；CBOE（备）：15 分钟延迟、免费。详见 [05_API文档](./05_API文档.md) 与 [09_Polygon集成](./09_Polygon集成.md)。 |

### 1. Supabase (BaaS)

**核心服务**:
- **PostgreSQL数据库**: 关系型数据存储
- **REST API**: 自动生成的RESTful API
- **Realtime**: WebSocket实时订阅
- **Auth**: 用户认证和授权
- **Storage**: 文件存储（未来使用）

**客户端初始化**:
```typescript
// src/lib/supabase.ts
import { createClient } from '@supabase/supabase-js';

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL;
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY;

export const supabase = createClient(supabaseUrl, supabaseKey);
```

**数据操作示例**:
```typescript
// 查询所有活跃持仓
const { data, error } = await supabase
  .from('positions')
  .select('*, transactions(*)')
  .eq('status', 'active')
  .order('created_at', { ascending: false });

// 插入新持仓
const { data, error } = await supabase
  .from('positions')
  .insert([{ ticker, strike, type, expiration, ... }])
  .select();

// 更新持仓价格
const { error } = await supabase
  .from('positions')
  .update({ current_price: newPrice })
  .eq('id', positionId);

// 删除持仓（级联删除transactions）
const { error } = await supabase
  .from('positions')
  .delete()
  .eq('id', positionId);
```

**API 端点**:

lib/polygon-client.js     # Polygon 客户端（DATA_SOURCE=POLYGON 时使用）
/api/option-price.js      # 单合约价格 + Greeks（Polygon 优先，CBOE 备用）

/api/check-alerts.js      # 止损/目标价 Discord 提醒（外部 Cron 触发，需 CRON_SECRET）

**期权数据源**：由环境变量 `DATA_SOURCE` 控制。`POLYGON` 时使用 Polygon.io（需 `POLYGON_API_KEY`），失败或未配置时降级 CBOE；未设置时默认 CBOE。详见 [09_Polygon集成](./09_Polygon集成.md) 与 [05_API文档](./05_API文档.md)。

**共享评分模块**:
- `api/_shared/scoring.cjs` 与 `src/lib/oss-core.ts` 保持逻辑一致（LERP Delta Bonus、Theta 上限 10、Lambda 压缩、Z-Score、**Vega 效率/惩罚 v2.4**、parseChain、getCleanATM_IV、calculateTargetIV、buildIVTermStructure 等），避免前后端/扫描器与持仓卡片分数不一致。

**Serverless 优势**:
- ✅ 零服务器管理
- ✅ 自动扩展
- ✅ 按需付费
- ✅ 全球边缘网络

**Vercel Hobby 计划注意事项**:
- Cron Jobs 仅支持每日一次频率，高频 cron（如 `*/15 * * * *`）会导致部署失败
- 解决方案：使用 [cron-job.org](https://cron-job.org) 外部 cron 服务，定时 GET 调用 API
- `vercel.json` 中**不应包含** `crons` 配置

**Discord 自动提醒**:
- `check-alerts.js` 通过 Supabase REST API（PostgREST）查询 Active 持仓
- 不使用 `@supabase/supabase-js` SDK，避免 Vercel Serverless 的 ESM import 兼容问题
- 当前价通过内部调用 `/api/option-price` 获取
- 触发条件匹配后，发送 Discord Webhook（Embed 格式，红色=止损，绿色=目标价）
- 由外部 cron-job.org 每 15 分钟触发

## 🔄 数据流设计

### 1. 数据获取流程

```
用户操作 → React组件 → Supabase Client → PostgreSQL
                ↓
         更新本地状态
                ↓
         重新渲染UI
```

**实现示例**:
```typescript
// Portfolio.tsx
const fetchPositions = async () => {
  setLoading(true);
  try {
    const { data, error } = await supabase
      .from('positions')
      .select('*, transactions(*)')
      .eq('status', 'active');
    
    if (error) throw error;
    setPositions(data);
  } catch (error) {
    console.error('Error fetching positions:', error);
  } finally {
    setLoading(false);
  }
};
```

### 2. 价格更新流程

```
用户点击"Refresh Prices" -> 触发 fetchGreeksAndPrice
    ↓
遍历所有 Leg (Short/Long)
    ↓
并发调用 /api/option-price 
    ↓
前端计算 Net Greeks, Net IV, 和 Net Price (Value)
    ↓
前端计算 Composite Score (基于 CSQ+/LOQ+ 算法)
    ↓
更新本地 liveData 状态 (确保 UI 立即响应，无抖动)
    ↓
[可选] 条件触发 Supabase positions 表更新
```

**稳定性优化**:
- **Local Cache First**: 即使数据库更新受限，`liveData` 也能保证当前显示的 P&L 和价格是实时的。
- **Conditional Update**: 只有当价格变动超过阈值或定时器触发时才更新数据库，防止高频刷新导致的重绘循环。
- **Score Consistency**: 借用 `scoring.ts` 中的统一算法，确保扫描器和持仓卡片看到的评分逻辑完全对齐。

### 3. Scanner 数据流

```
用户输入 Ticker + 策略（Long/Short）+ 可选 Day Trade
    ↓
前端请求 GET /api/scan-options?ticker=...&strategy=...
    ↓
Vercel 函数按 DATA_SOURCE 拉取期权链（Polygon 优先，CBOE 备用）
    ↓
api/_shared/scoring.cjs 解析（parseChain 兼容双格式）+ 过滤 + 指标计算
    ↓
单遍过滤（DTE、Strike、Volume、Spread、bid/ask>0）+ 计算 Lambda/GammaEff/ThetaBurn 或 POP/Edge
    ↓
Lambda 压缩 → Z-Score 标准化 → LOQ/CSQ 加权（含 Day Trade 权重）→ 0–100 归一化
    ↓
按得分排序，返回 Top 20
    ↓
前端展示，用户可添加到 Watchlist
```

（持仓卡片上的分数由前端 `scoring.ts` 使用同一套 oss-core 逻辑计算，与扫描结果一致。）

## 🔌 API集成

### 1. 期权数据源（双源架构）

**配置**：环境变量 `DATA_SOURCE=POLYGON`（需 `POLYGON_API_KEY`）或 `CBOE`/未设置。未设置时默认 CBOE。

| 数据源 | 说明 |
|--------|------|
| **Polygon.io** | 主源；实时报价，Greeks + IV；仅请求所需 DTE/行权 + 1 分钟缓存；供 option-price、scan-options、strategy-recommend、check-alerts、daily-recap 使用 |
| **CBOE** | 备用；15 分钟延迟，免费；Greeks 在 API 中为 0 |

**CBOE 端点**（备用）:
```
https://cdn.cboe.com/api/global/delayed_quotes/options/{TICKER}.json
```

**CBOE 数据结构**（scoring.cjs 中 parseChain 可解析）:
```json
{
  "data": {
    "current_price": 620.24,
    "options": [
      {
        "option": "QQQ260220C00630000",
        "bid": 7.32,
        "ask": 7.39,
        "last_trade_price": 7.35,
        "delta": 0,
        "gamma": 0,
        "theta": 0,
        "vega": 0,
        "iv": 0,
        "volume": 6485,
        "open_interest": 29600
      }
    ]
  }
}
```
CBOE 与 Polygon 返回格式与字段命名不同（如 symbol、last、openInterest），由 `parseChain()` 自动识别。

**OCC Symbol生成**:
```javascript
function generateOCCSymbol(symbol, expiration, type, strike) {
  // QQQ   260220C00630000
  // ^^^   ^^^^^^ ^^^^^^^^
  // 股票  日期   类型+行权价
  
  const paddedSymbol = symbol.padEnd(6, ' ');
  const [year, month, day] = expiration.split('-');
  const dateStr = `${year.slice(2)}${month}${day}`;
  const typeCode = type[0].toUpperCase(); // C or P
  const strikeStr = (strike * 1000).toString().padStart(8, '0');
  
  return `${paddedSymbol}${dateStr}${typeCode}${strikeStr}`;
}
```

### 2. 错误处理

**重试机制**:
```typescript
async function fetchWithRetry(url: string, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url);
      if (response.ok) return response;
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, 1000 * (i + 1)));
    }
  }
}
```

**降级策略**:

### Vercel 环境变量

| 变量名 | 说明 |
|--------|------|
| `VITE_SUPABASE_URL` | Supabase 项目 URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase Anon Key |

### Vercel Hobby 计划限制

- **Cron**：仅支持每日一次；`*/15 * * * *` 会导致部署失败，故 `vercel.json` 中不要配置高频 crons，改用 [cron-job.org](https://cron-job.org) 等外部定时触发。
- **Serverless 超时**：默认 10s，可配置至 60s。

### 故障排除

**价格获取失败**：检查网络与参数；Polygon 时确认 `DATA_SOURCE=POLYGON` 与 `POLYGON_API_KEY`；CBOE 可能 429，可稍后重试或用手动输入。

**常见错误**：

| 错误 | 原因 | 解决 |
|------|------|------|
| "Option contract not found" | 合约不存在或已过期 | 检查到期日 |
| "CBOE API error: 404" | Ticker 不支持 | 确认美股期权 |
| Polygon 401/403 | API Key 无效或过期 | 检查 `POLYGON_API_KEY` |
| 响应 Greeks 全为 0 | 使用 CBOE 或未配 Polygon | 配置 `DATA_SOURCE` 与 `POLYGON_API_KEY` 后重新部署 |

**部署问题**：

| 问题 | 原因 | 解决 |
|------|------|------|
| 推送后 Vercel 未自动部署 | Webhook 断连 | 用 Deploy Hook 或 `npx vercel --prod` |
| 报 "Hobby accounts are limited to daily cron jobs" | `vercel.json` 含高频 crons | 删除 `crons` 配置，改用外部 cron |
| 新 API 404 但旧端点正常 | 未用最新部署 | 确认最新部署为 Ready，查看 Build Logs |

## 📝 开发说明与重构历史

- **评分统一**：getDeltaBonus（LERP）、getThetaPenalty（上限 10）、Lambda 压缩、Day Trade 权重；前后端与 API 均使用 `oss-core` / `_shared/scoring.cjs` 单点事实。
- **类型与边界**：WatchlistItem、DirectAddItem（含 legs）、StrategyResult、UnifiedCandidateType 等；数学边界在 oss-core 中统一防护。
- **API 用量**：Polygon 下仅请求所需 DTE/行权，期权链 1 分钟内存缓存；详见 [09_Polygon集成](./09_Polygon集成.md)。
- **Discord 提醒**：`check-alerts.js` 用 Supabase REST API + 外部 cron 每 15 分钟触发；详见 [07_止损与目标价短信提醒方案](./07_止损与目标价短信提醒方案.md)。
- **跨策略统一评分 / Top Picks**：`calculateUnifiedScore` 统一 Credit/Debit/Long 排序；单腿 POP 与价差一致（breakeven-based）；Skew/Regime 细粒度见 `scoring.cjs`。
- **价差 Quick Add / Spread Width**：Portfolio 支持 Single Leg / Credit / Debit Spread；策略推荐 Spread Width 可配置（$2.5/$5/$10/$20）。

更细的算法演进见 [算法改进总览_OSS_v2.2](./算法改进总览_OSS_v2.2.md)，版本记录见项目根目录 [CHANGELOG.md](../CHANGELOG.md)。
