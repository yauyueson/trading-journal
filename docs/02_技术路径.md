## 🎨 前端技术栈

### 1. React 18 + TypeScript

**选择理由**:
- **类型安全**: TypeScript减少运行时错误，提升代码质量
- **组件化**: React组件化开发，代码复用性高
- **生态成熟**: 丰富的第三方库和工具链
- **Hooks**: 简化状态管理和副作用处理

```typescript
// 性能优化
```

**评分架构说明**:
- `oss-core.ts`: 所有原始公式的唯一实现（lerp、sigmoid、compressLambda、getDeltaBonus、getThetaPenalty、LOQ/CSQ 权重、normalizeToZScores、价差评分等），含边缘情况防护。
- `scoring.ts`: 从 oss-core 复用并 re-export；额外提供 `scoreOptionsChain`（批量+Day Trade）、`calculateIVRatio`（4-Card IV 期限结构）。
- API 层使用 `api/_shared/scoring.js`（与 oss-core 逻辑同步），保证扫描器、策略推荐与前端持仓卡片分数一致。

**组件设计原则**:
1. **单一职责**: 每个组件只负责一个功能
2. **Props接口**: 明确的TypeScript接口定义
3. **状态提升**: 共享状态提升到父组件
4. **纯函数**: 尽可能使用纯函数组件

## 🔧 后端架构

### 1. Supabase (BaaS)

**核心服务**:
- **PostgreSQL数据库**: 关系型数据存储
- **REST API**: 自动生成的RESTful API
- **Realtime**: WebSocket实时订阅
- **Auth**: 用户认证和授权
- **Storage**: 文件存储（未来使用）

**客户端初始化**:
```typescript
// src/lib/supabase.ts
import { createClient } from '@supabase/supabase-js';

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL;
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY;

export const supabase = createClient(supabaseUrl, supabaseKey);
```

**数据操作示例**:
```typescript
// 查询所有活跃持仓
const { data, error } = await supabase
  .from('positions')
  .select('*, transactions(*)')
  .eq('status', 'active')
  .order('created_at', { ascending: false });

// 插入新持仓
const { data, error } = await supabase
  .from('positions')
  .insert([{ ticker, strike, type, expiration, ... }])
  .select();

// 更新持仓价格
const { error } = await supabase
  .from('positions')
  .update({ current_price: newPrice })
  .eq('id', positionId);

// 删除持仓（级联删除transactions）
const { error } = await supabase
  .from('positions')
  .delete()
  .eq('id', positionId);
```

### 2. Vercel Serverless Functions

**API 端点**:
```
api/_shared/scoring.js   # 共享评分逻辑（与 src/lib/oss-core.ts 镜像），供下列 API 引用
/api/option-price.js     # 单合约价格 + Greeks
/api/scan-options.js     # OSS 扫描器（Long/Short + Day Trade）
/api/strategy-recommend.js # 策略推荐（Credit/Debit Spread + Single Leg）
/api/underlying-rv.js    # 标的已实现波动率
/api/earnings.js         # 财报日期
/api/check-alerts.js     # 止损/目标价 Discord 提醒（外部 Cron 触发，需 CRON_SECRET）
/api/health.js           # 部署健康检查
```

**共享评分模块**:
- `api/_shared/scoring.js` 与 `src/lib/oss-core.ts` 保持逻辑一致（LERP Delta Bonus、Theta 上限 10、Lambda 压缩、Z-Score、parseChain、getCleanATM_IV、calculateTargetIV 等），避免前后端/扫描器与持仓卡片分数不一致。

**Serverless 优势**:
- ✅ 零服务器管理
- ✅ 自动扩展
- ✅ 按需付费
- ✅ 全球边缘网络

**Vercel Hobby 计划注意事项**:
- Cron Jobs 仅支持每日一次频率，高频 cron（如 `*/15 * * * *`）会导致部署失败
- 解决方案：使用 [cron-job.org](https://cron-job.org) 外部 cron 服务，定时 GET 调用 API
- `vercel.json` 中**不应包含** `crons` 配置

**Discord 自动提醒**:
- `check-alerts.js` 通过 Supabase REST API（PostgREST）查询 Active 持仓
- 不使用 `@supabase/supabase-js` SDK，避免 Vercel Serverless 的 ESM import 兼容问题
- 当前价通过内部调用 `/api/option-price` 获取
- 触发条件匹配后，发送 Discord Webhook（Embed 格式，红色=止损，绿色=目标价）
- 由外部 cron-job.org 每 15 分钟触发

**函数结构**:
```javascript
// api/option-price.js
export default async function handler(req, res) {
  res.setHeader('Access-Control-Allow-Origin', '*');
  const { ticker, expiration, strike, type } = req.query;
  if (!ticker || !expiration || !strike || !type) {
    return res.status(400).json({ error: 'Missing parameters' });
  }
  const cboeUrl = `https://cdn.cboe.com/api/global/delayed_quotes/options/${ticker}.json`;
  const response = await fetch(cboeUrl);
  const data = await response.json();
  return res.status(200).json({ success: true, ... });
}
```

## 🔄 数据流设计

### 1. 数据获取流程

```
用户操作 → React组件 → Supabase Client → PostgreSQL
                ↓
         更新本地状态
                ↓
         重新渲染UI
```

**实现示例**:
```typescript
// Portfolio.tsx
const fetchPositions = async () => {
  setLoading(true);
  try {
    const { data, error } = await supabase
      .from('positions')
      .select('*, transactions(*)')
      .eq('status', 'active');
    
    if (error) throw error;
    setPositions(data);
  } catch (error) {
    console.error('Error fetching positions:', error);
  } finally {
    setLoading(false);
  }
};
```

### 2. 价格更新流程

```
用户点击"Refresh Prices" -> 触发 fetchGreeksAndPrice
    ↓
遍历所有 Leg (Short/Long)
    ↓
并发调用 /api/option-price 
    ↓
前端计算 Net Greeks, Net IV, 和 Net Price (Value)
    ↓
前端计算 Composite Score (基于 CSQ+/LOQ+ 算法)
    ↓
更新本地 liveData 状态 (确保 UI 立即响应，无抖动)
    ↓
[可选] 条件触发 Supabase positions 表更新
```

**稳定性优化**:
- **Local Cache First**: 即使数据库更新受限，`liveData` 也能保证当前显示的 P&L 和价格是实时的。
- **Conditional Update**: 只有当价格变动超过阈值或定时器触发时才更新数据库，防止高频刷新导致的重绘循环。
- **Score Consistency**: 借用 `scoring.ts` 中的统一算法，确保扫描器和持仓卡片看到的评分逻辑完全对齐。

### 3. Scanner 数据流

```
用户输入 Ticker + 策略（Long/Short）+ 可选 Day Trade
    ↓
前端请求 GET /api/scan-options?ticker=...&strategy=...
    ↓
Vercel 函数拉取 CBOE 期权链，api/_shared/scoring 解析 + 过滤 + 指标计算
    ↓
单遍过滤（DTE、Strike、Volume、Spread、bid/ask>0）+ 计算 Lambda/GammaEff/ThetaBurn 或 POP/Edge
    ↓
Lambda 压缩 → Z-Score 标准化 → LOQ/CSQ 加权（含 Day Trade 权重）→ 0–100 归一化
    ↓
按得分排序，返回 Top 20
    ↓
前端展示，用户可添加到 Watchlist
```

（持仓卡片上的分数由前端 `scoring.ts` 使用同一套 oss-core 逻辑计算，与扫描结果一致。）

## 🔌 API集成

### 1. CBOE API

**端点**:
```
https://cdn.cboe.com/api/global/delayed_quotes/options/{TICKER}.json
```

**数据结构**:
```json
{
  "data": {
    "current_price": 620.24,
    "options": [
      {
        "option": "QQQ260220C00630000",
        "bid": 7.32,
        "ask": 7.39,
        "last_trade_price": 7.35,
        "delta": 0.3999,
        "gamma": 0.0123,
        "theta": -0.0456,
        "vega": 0.0789,
        "iv": 0.1778,
        "volume": 6485,
        "open_interest": 29600
      }
    ]
  }
}
```

**OCC Symbol生成**:
```javascript
function generateOCCSymbol(symbol, expiration, type, strike) {
  // QQQ   260220C00630000
  // ^^^   ^^^^^^ ^^^^^^^^
  // 股票  日期   类型+行权价
  
  const paddedSymbol = symbol.padEnd(6, ' ');
  const [year, month, day] = expiration.split('-');
  const dateStr = `${year.slice(2)}${month}${day}`;
  const typeCode = type[0].toUpperCase(); // C or P
  const strikeStr = (strike * 1000).toString().padStart(8, '0');
  
  return `${paddedSymbol}${dateStr}${typeCode}${strikeStr}`;
}
```

### 2. 错误处理

**重试机制**:
```typescript
async function fetchWithRetry(url: string, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url);
      if (response.ok) return response;
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, 1000 * (i + 1)));
    }
  }
}
```

**降级策略**:
