### OSS 评分架构（单点事实）

| 层级 | 文件 | 职责 |
|------|------|------|
| **规范源** | `src/lib/oss-core.ts` | LOQ/CSQ/Delta Bonus/Theta 惩罚/Lambda 压缩/Z-Score/价差评分；v2.4 Vega；LERP、Sigmoid、边缘防护 |
| **前端复用** | `src/lib/scoring.ts` | 从 oss-core re-export；`scoreOptionsChain`、IV 期限结构 `calculateIVRatio` |
| **API 镜像** | `api/_shared/scoring.cjs` | 与 oss-core 逻辑同步的 JS 实现，供 scan-options、strategy-recommend 引用；含跨策略统一评分 |

**原则**：不在此三处以外重复实现评分公式，保证扫描器与持仓卡片分数一致。

| 技术 | 选择理由 |
|------|----------|
| React 18 + TypeScript | 组件化、类型安全、生态成熟 |
| React Router v6 | 客户端路由，每页独立 URL，懒加载代码分割 |

| **期权数据** | ORATS（期权链/Greeks/IV/cores/earnings/impliedMove）+ Tiingo（股票K线）。详见 [05_API文档](./05_API文档.md)。 |

## 🎨 前端技术栈

### 1. React 18 + TypeScript

**选择理由**:
- **类型安全**: TypeScript减少运行时错误，提升代码质量
- **组件化**: React组件化开发，代码复用性高
- **生态成熟**: 丰富的第三方库和工具链
- **Hooks**: 简化状态管理和副作用处理

**核心 Hooks 使用（v3.0 架构）**:
```typescript
// 页面通过 hooks 自行获取数据，不再依赖 App.tsx prop drilling
import { usePositions } from '../hooks/usePositions';
import { useTransactions } from '../hooks/useTransactions';
import { usePositionAction } from '../hooks/usePositionMutations';

// React Query 自动缓存 + 失效
const { data: positions = [], isLoading } = usePositions();
const { data: transactions = [] } = useTransactions();

// Mutation hooks 替代 9+ 回调 props
const positionAction = usePositionAction();
positionAction.mutate({ id, action }); // 自动失效 positions + transactions 缓存

// React Router 路由
import { useNavigate, useLocation } from 'react-router-dom';
const navigate = useNavigate();
const currentPath = useLocation().pathname;
```

**评分架构说明**:
- `oss-core.ts`: 所有原始公式的唯一实现（lerp、sigmoid、compressLambda、getDeltaBonus、getThetaPenalty、LOQ/CSQ 权重、**v2.4 Vega 效率/惩罚**、normalizeToZScores、价差评分等），含边缘情况防护。
- `scoring.ts`: 从 oss-core 复用并 re-export；额外提供 `scoreOptionsChain`（批量+Day Trade）、`calculateIVRatio`（4-Card IV 期限结构）。
- API 层使用 `api/_shared/scoring.cjs`（与 oss-core 逻辑同步），保证扫描器、策略推荐与前端持仓卡片分数一致。

**组件设计原则（v3.0）**:
1. **自治页面**: 页面通过 hooks 自行获取数据，不依赖父组件传递 props
2. **Mutation hooks**: 所有数据修改通过 `usePositionMutations.ts` 中的 hooks，自动失效缓存
3. **Context 仅用于跨组件状态**: Auth、BuyModal、AppSettings；数据获取用 React Query
4. **纯函数**: 评分逻辑在 `oss-core.ts` 中保持纯函数，便于测试

## 🔧 后端架构

### 1. Supabase (BaaS)

**核心服务**:
- **PostgreSQL数据库**: 关系型数据存储
- **REST API**: 自动生成的RESTful API
- **Realtime**: WebSocket实时订阅
- **Auth**: 用户认证和授权
- **Storage**: 文件存储（未来使用）

**客户端初始化**:
```typescript
// src/lib/supabase.ts
import { createClient } from '@supabase/supabase-js';

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL;
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY;

export const supabase = createClient(supabaseUrl, supabaseKey);
```

**数据操作示例**:
```typescript
// 查询所有活跃持仓
const { data, error } = await supabase
  .from('positions')
  .select('*, transactions(*)')
  .eq('status', 'active')
  .order('created_at', { ascending: false });

// 插入新持仓
const { data, error } = await supabase
  .from('positions')
  .insert([{ ticker, strike, type, expiration, ... }])
  .select();

// 更新持仓价格
const { error } = await supabase
  .from('positions')
  .update({ current_price: newPrice })
  .eq('id', positionId);

// 删除持仓（级联删除transactions）
const { error } = await supabase
  .from('positions')
  .delete()
  .eq('id', positionId);
```

- `api/_shared/scoring.cjs` 与 `src/lib/oss-core.ts` 保持逻辑一致（LERP Delta Bonus、Theta 上限 10、Lambda 压缩、Z-Score、**Vega 效率/惩罚 v2.4**、parseChain、getCleanATM_IV、calculateTargetIV、buildIVTermStructure 等），避免前后端/扫描器与持仓卡片分数不一致。

**Serverless 优势**:
- ✅ 零服务器管理
- ✅ 自动扩展
- ✅ 按需付费
- ✅ 全球边缘网络

**Vercel Hobby 计划注意事项**:
- Cron Jobs 仅支持每日一次频率，高频 cron（如 `*/15 * * * *`）会导致部署失败

- 由外部 cron-job.org 每 15 分钟触发

## 🔄 数据流设计

### 1. 数据获取流程（React Query）

```
页面组件 → usePositions() hook → React Query cache check
                                      │
                        ┌──── 命中 ────┤──── 未命中/过期 ────┐
                        ▼              │                     ▼
                   返回缓存数据         │            Supabase Client → PostgreSQL
                                      │                     │
                                      │              更新缓存 + 重新渲染
                                      │
Supabase Realtime 事件 → useRealtimeInvalidation() → invalidateQueries()
```

**实现示例**:
```typescript
// src/hooks/usePositions.ts
export function usePositions() {
  return useQuery({
    queryKey: queryKeys.positions(),
    queryFn: async () => {
      const { data, error } = await supabase.from('positions').select('*');
      if (error) throw error;
      return data as Position[];
    },
  });
}

// Portfolio.tsx — 页面直接使用 hook，无需父组件传递
const { data: positions = [], isLoading } = usePositions();
```

### 2. 价格更新流程

```
用户点击"Refresh Prices" -> 触发 fetchGreeksAndPrice
    ↓
遍历所有 Leg (Short/Long)
    ↓
并发调用 /api/option-price 
    ↓
前端计算 Net Greeks, Net IV, 和 Net Price (Value)
    ↓
前端计算 Composite Score (基于 CSQ+/LOQ+ 算法)
    ↓
更新本地 liveData 状态 (确保 UI 立即响应，无抖动)
    ↓
[可选] 条件触发 Supabase positions 表更新
```

**稳定性优化**:
- **Local Cache First**: 即使数据库更新受限，`liveData` 也能保证当前显示的 P&L 和价格是实时的。
- **Conditional Update**: 只有当价格变动超过阈值或定时器触发时才更新数据库，防止高频刷新导致的重绘循环。
- **Score Consistency**: 借用 `scoring.ts` 中的统一算法，确保扫描器和持仓卡片看到的评分逻辑完全对齐。

### 3. Scanner 数据流

```
用户输入 Ticker + 策略（Long/Short）+ 可选 Day Trade
    ↓
前端请求 GET /api/scan-options?ticker=...&strategy=...
    ↓
Vercel 函数通过 ORATS 拉取期权链
    ↓
api/_shared/scoring.cjs 解析（parseChain 兼容双格式）+ 过滤 + 指标计算
    ↓
单遍过滤（DTE、Strike、Volume、Spread、bid/ask>0）+ 计算 Lambda/GammaEff/ThetaBurn 或 POP/Edge
    ↓
Lambda 压缩 → Z-Score 标准化 → LOQ/CSQ 加权（含 Day Trade 权重）→ 0–100 归一化
    ↓
按得分排序，返回 Top 20
    ↓
前端展示，用户可添加到 Watchlist
```

（持仓卡片上的分数由前端 `scoring.ts` 使用同一套 oss-core 逻辑计算，与扫描结果一致。）

**OCC Symbol生成**:
```javascript
function generateOCCSymbol(symbol, expiration, type, strike) {
  // QQQ   260220C00630000
  // ^^^   ^^^^^^ ^^^^^^^^
  // 股票  日期   类型+行权价
  
  const paddedSymbol = symbol.padEnd(6, ' ');
  const [year, month, day] = expiration.split('-');
  const dateStr = `${year.slice(2)}${month}${day}`;
  const typeCode = type[0].toUpperCase(); // C or P
  const strikeStr = (strike * 1000).toString().padStart(8, '0');
  
  return `${paddedSymbol}${dateStr}${typeCode}${strikeStr}`;
}
```

```typescript
async function fetchWithRetry(url: string, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url);
      if (response.ok) return response;
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, 1000 * (i + 1)));
    }
  }
}
```
